# 阶段八：动效、性能与兼容优化

阶段八已完成。此阶段没有引入 CDN、远程字体、外部数据库或新的运行时依赖，应用版本升级为 `0.8.0`，数据库结构没有变化，因此现有站点升级时不需要执行新的迁移。

## 完成内容

- 为页面切换、卡片按压、图片渐入、抽屉和对话框补充轻量物理反馈；支持系统减少动态效果和站内手动精简动效。
- 根据设备内存和逻辑处理器数量自动启用低性能模式，关闭持续动画、背景模糊和高成本阴影。
- 图片使用固有尺寸、稳定宽高比、懒加载、异步解码和本地渐进显示；文章只允许引用本地媒体地址。
- 静态资源使用版本查询参数和一年不可变缓存，文本响应按客户端能力使用 gzip；开发模式使用 `no-cache`，避免调试时命中旧资源。
- 本地媒体使用严格随机文件名校验、零数据库查询交付、ETag 和条件请求；Atom 与站点地图支持短时缓存和条件请求。
- 将导航、站点资料和页脚设置放入进程内短期缓存；后台成功写操作会立即失效缓存。
- 将首页多个设置读取合并为一次查询，删除友链页面的无效查询，后台媒体库改为分页。
- SQLite 补充内存临时表、8 MiB 页面缓存、自动 WAL 检查点和 `db-optimize` 维护命令。
- 完成 320–1440 CSS 像素响应式、键盘焦点约束、焦点返回、语义状态、强制色彩、打印和无背景模糊降级。
- 修复极窄后台页面与手机留言/评论表单的横向溢出。

## 升级与维护

更新代码并重启 Waitress/Gunicorn 即可应用本阶段优化。可在日常低流量时执行：

```powershell
.\.venv\Scripts\flask.exe --app app:create_app db-optimize
```

需要主动回收已完成检查点的 WAL 文件空间时，在低流量维护窗口执行：

```powershell
.\.venv\Scripts\flask.exe --app app:create_app db-optimize --truncate
```

`--truncate` 可能短暂等待正在使用数据库的连接，因此不建议在写入高峰执行。
