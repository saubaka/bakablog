# 兼容性、响应式与无障碍报告

## 实际浏览器验收

在本机 Chromium/Edge 内核浏览器中实际打开 Waitress 站点并检查：

| 场景 | CSS 视口 | 结果 |
| --- | ---: | --- |
| 桌面首页 | 1440×1000 | 导航、首屏、卡片网格稳定，无横向溢出 |
| iPad/平板博客 | 1024×768 | 搜索、筛选、文章列表和分页正常 |
| iPhone 首页/友链/留言 | 390×844 | 底部导航、抽屉、长列表和表单正常 |
| Android 文章/评论 | 360×800 | 正文和评论表单无横向溢出 |
| 极窄后台登录 | 320×700 | 标签、输入框、按钮完整显示，无横向溢出 |

控制台错误和警告为 0。运行时 CSS、JavaScript、图标和图片均来自本地站点；站点元信息中的本机 URL 不属于远程运行依赖。

## 键盘与动效

- 页面首个可聚焦元素为“跳到主要内容”。
- 手机抽屉打开后焦点进入“关闭菜单”，Tab 焦点保持在抽屉内；Esc 关闭后返回触发按钮。
- 原生 `dialog` 可用时使用浏览器模态焦点行为，不支持时退化为 `open` 属性。
- 当前页面导航包含 `aria-current="page"`。
- 自动保存和图片上传状态使用 `role="status"` 与礼貌播报。
- 动效开关将偏好保存在本地；精简后实测卡片动画/过渡时长为 `0.00001s`，并停止持续漂浮和高成本装饰。
- 系统 `prefers-reduced-motion` 会自动生效；旧版保存的 `full` 值会迁移为跟随系统。

## 对比度

按 WCAG 相对亮度公式测量：

| 前景/背景 | 对比度 |
| --- | ---: |
| 主文字 / 白色 | 10.47:1 |
| 次级文字 / 白色 | 4.97:1 |
| 弱化文字 / 白色 | 4.88:1 |
| 主蓝 / 白色 | 4.84:1 |
| 弱化文字 / 浅灰画布 | 4.63:1 |
| 主蓝 / 浅灰画布 | 4.59:1 |

普通正文和承载意义的蓝色文字均达到 AA 的 4.5:1 要求。焦点使用 3px 可见轮廓，手机底部导航触控高度实测为 52px。

## 渐进增强与兼容处理

- `View Transitions`、`content-visibility`、`backdrop-filter` 均为可选增强；不支持时页面仍保持标准文档流和完整功能。
- 同时提供 `-webkit-backdrop-filter` 和无模糊背景回退。
- 提供 `prefers-contrast: more`、`forced-colors: active`、`hover: none` 和打印样式。
- 图片具有固有尺寸或 CSS 宽高比，失败时保留稳定容器；JavaScript 仅增加渐入和灯箱，不影响基础阅读。
- 低性能模式依据 `hardwareConcurrency`/`deviceMemory` 保守启用；不支持这些属性时保持标准模式。

## 已知边界

- 本轮可实际运行的桌面浏览器为 Chromium/Edge 内核；Safari/WebKit 与 Firefox 的处理基于标准 CSS 降级和前缀审查，正式发布前仍应在目标真实设备做一次最终冒烟测试。
- 浏览器缩放不能在当前自动化环境中稳定控制，因此以 320 CSS 像素极窄视口覆盖高缩放下最容易暴露的重排问题；阶段九发布验收仍需补充真实 200% 缩放操作。
- gzip 在 Flask 层完成，适合当前单机规模；若阶段九启用反向代理，应只保留一层压缩并由代理优先处理。
