# 独特可爱风个人网站分阶段实施方案

## 1. 执行原则

整个项目拆分为九个阶段。每个阶段可占用一次或多次对话，必须遵守以下规则：

1. 开始阶段前，检查项目目录、现有文档和上一阶段验收记录。
2. 只实现当前阶段范围，不提前堆积后续业务代码。
3. 每个阶段结束时运行与风险相匹配的检查和测试。
4. 在本文档中更新状态、完成项、测试结果和遗留问题。
5. 验收通过后再进入下一阶段。
6. 对跨阶段产生影响的决定，写入项目决策记录，不能只保留在对话中。
7. 固定使用Python、Flask、Jinja2、SQLite和本地文件存储，不再更换主体技术栈。
8. 所有Python包安装在本地虚拟环境，所有浏览器资源随项目本地提供，运行时不依赖CDN或云服务。
9. 高性能优化以单机、读多写少为边界，必须尊重SQLite单写入者模型并保留性能测试证据。

## 3. 阶段一：需求确认与技术方案

### 目标

在已确定Python、Flask、SQLite和全本地依赖的前提下，明确网站范围、首发版本、部署环境和项目结构，消除后续开发中的关键歧义。

### 任务

- 确认网站名称、主题概念、内容类型和目标访客。
- 确认首发页面、后台功能与可延后功能。
- 确认是否开放注册、评论、友链申请和私密内容。
- 确认目标操作系统、Python版本范围、域名、HTTPS和单机部署条件。
- 固化Flask应用工厂、Blueprint、Jinja2、SQLAlchemy、SQLite和本地文件存储方案。
- 确认生产WSGI服务：Linux优先Gunicorn，Windows使用Waitress；本地反向代理为可选项。
- 确认所有字体、图标、CSS、JavaScript、上传文件和第三方前端库的本地化规则。
- 设计Python虚拟环境、依赖锁定文件和可选本地`wheelhouse`离线安装流程。
- 制定SQLite WAL、外键、繁忙超时、索引、短事务、FTS5、备份和完整性检查策略。
- 设计项目目录、环境变量和开发、测试、生产环境。
- 初步设计数据模型和前后台权限边界。
- 建立需求、架构和决策记录文档。

### 交付物

- 需求规格说明。
- Flask本地化架构与依赖清单。
- SQLite性能、安全、备份和并发边界说明。
- 本地静态资源、媒体和离线依赖管理说明。
- 页面和功能清单。
- 数据实体与权限清单。
- 项目目录规划。
- 首发版本范围与后续功能列表。

### 验收标准

- 每个公开页面都能找到对应的后台管理能力。
- Flask、SQLite和本地存储方案与实际单机部署条件匹配。
- 文档中不存在CDN、对象存储、外部数据库或Redis等运行时强制依赖。
- 明确SQLite适合读多写少、单机部署，不承诺多机并发写入。
- 首发范围明确，不存在必须边开发边猜测的关键事项。
- 项目目录和命名规则可以直接用于初始化代码。

- 新增或修改文件：`docs/phase-1/`下八份阶段文档，并更新根目录索引、总体规划和本阶段状态。

## 4. 阶段二：视觉规范与页面原型

### 目标

把“简约可爱、浅色、丝滑”转化为可执行的视觉和交互规范。

### 任务

- 确定配色、字体、字号、间距、圆角、边框和阴影变量。
- 设计桌面、平板和移动端布局规则。
- 设计首页、博客列表、文章详情、关于、友链和后台原型。
- 定义导航、卡片、按钮、表单、弹窗、提示和空状态。
- 定义加载、错误、成功、禁用和骨架屏状态。
- 设计物理动效参数、页面过渡和动画降级规则。
- 验证文字对比度、键盘焦点和触控尺寸。

### 交付物

- 设计变量和主题规范。
- 核心页面线框图或高保真原型。
- 响应式布局说明。

### 验收标准

- 核心页面在三类设备上都有明确布局。
- 前台和后台使用同一套基础设计语言。
- 所有组件都定义默认、悬停、按下、焦点、禁用和错误状态。
- 视觉装饰不影响阅读、键盘操作或触控。

### 验收标准

- 主要占位页面可以正常跳转和刷新。

## 6. 阶段四：数据库、登录与后台基础

### 目标

完成内容管理系统所需的数据、认证、权限和媒体基础设施。

### 任务

- 使用SQLAlchemy实现SQLite数据模型、Alembic迁移和初始化数据。
- 为每个SQLite连接启用外键、WAL和繁忙超时，验证配置实际生效。
- 为列表、状态、发布时间、排序和关联查询建立必要索引。
- 实现管理员登录、退出和会话保持。
- 实现角色、权限与服务端权限校验。
- 建立后台仪表盘和常用快捷入口。
- 建立统一API响应、输入验证和错误处理。
- 使用本地目录实现媒体上传、列表、删除、格式校验和Pillow缩略图处理。
- 实现后台操作日志和登录日志。
- 提供SQLite在线备份、完整性检查、WAL维护以及数据库与媒体目录联合恢复流程。

### 交付物

- 数据库模型和迁移文件。
- 管理员账号、登录页面和权限系统。
- 后台仪表盘。
- 媒体库基础版。
- API、日志、备份和错误处理基础设施。

### 验收标准

- 未登录用户无法访问后台受保护页面和接口。
- 不同角色只能执行已授权操作。
- 图片能够上传、预览和删除。
- 数据库能够从空环境完成初始化和迁移。
- SQLite外键、WAL、繁忙超时、索引和备份恢复经过自动化验证。
- 并发写入出现锁等待时能够在限定时间内成功或返回可理解的错误，不静默丢失数据。
- 关键后台操作能够追溯到操作者。
