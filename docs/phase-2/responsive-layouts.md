# 响应式布局规范

## 1. 断点体系

布局采用内容驱动断点，不按具体设备品牌设计。

| 范围 | 名称 | 布局策略 |
| --- | --- | --- |
| 320～639px | Compact | 单列、底部导航、抽屉菜单 |
| 640～959px | Medium | 单列或两列、顶部紧凑导航 |
| 960～1279px | Desktop | 主内容+辅助栏、悬浮胶囊导航 |
| 1280px以上 | Wide | 最大宽度容器、完整非对称网格 |

最低支持宽度为320px。页面最大内容宽度为1280px，文章正文最大宽度为760px。

## 2. 公共框架

### Compact

- 页面水平留白16px。
- 顶部显示站点标识和搜索入口。
- 底部固定五项导航并适配安全区域。
- “更多”打开底部抽屉。
- 所有主要内容单列，水平滚动只允许代码块和明确的滑动组件。

### Medium

- 页面水平留白24～32px。
- 顶部使用紧凑胶囊导航。
- 首页部分卡片可两列，文章保持单列。
- 辅助信息进入正文前后或可折叠区域。

### Desktop/Wide

- 页面水平留白32～48px并居中。
- 顶部或左侧悬浮胶囊导航。
- 内容区使用12列网格，列间距20～24px。
- 文章页使用正文8列、目录3列和1列呼吸空间。

## 3. 首页布局

### Wide

- 欢迎卡占7列×2行。
- 当前状态卡占5列。
- 快捷信息或语录占5列。
- 精选文章使用8列，项目/动态组合使用4列。
- 友链和相册预览跨12列但内部使用自适应网格。

### Desktop

- 欢迎卡占8列，状态卡占4列。
- 文章列表占8列，右侧辅助内容占4列。
- 后续模块可改为6+6或整行。

### Medium/Compact

- 依次为欢迎、状态、精选文章、项目、动态、相册、友链。
- 取消视觉上依赖跨行的布局。
- 装饰元素降低透明度和数量。

## 4. 博客列表

- Wide：主列表8列，筛选侧栏4列；文章卡可使用图文横排。
- Desktop：主列表9列，筛选3列。
- Medium：筛选转为顶部横向胶囊或折叠面板，文章两列或单列。
- Compact：文章单列，封面比例约16:10，筛选通过按钮打开抽屉。

排序、分类和标签在所有尺寸都能访问，不能在移动端直接消失。

## 5. 文章详情

- Wide/Desktop：正文居中，右侧目录粘性定位；左侧可放轻量阅读进度。
- Medium：目录变为正文顶部的可折叠卡片。
- Compact：正文占满可用宽度，代码块横向滚动，表格放入可滚动容器。
- 标题、摘要和元信息不与封面叠加，以保证可读性。
- 上下篇、相关文章和评论在正文后按单列排列。

## 6. 关于与友链

- 关于页Wide使用个人档案4列+介绍8列，时间线随后整行。
- 移动端头像、简介、状态、技能、经历顺序展示。
- 友链Wide使用3～4列卡片，Medium两列，Compact单列。
- 友链申请表桌面使用双列字段，移动端单列。

## 7. 后台布局

### Desktop/Wide

- 左侧固定220～248px导航，顶部52～64px工具栏。
- 主区最大宽度不强制固定，表格和编辑器使用可用空间。
- 仪表盘统计卡4列，内容区8+4布局。

### Medium

- 左侧栏收起为图标栏或抽屉。
- 统计卡2列，表格隐藏低优先字段。

### Compact

- 顶部工具栏+左侧抽屉。
- 统计卡单列或2列。
- 数据表优先转为信息卡；确需表格时提供横向滚动和固定操作列。
- 保存、发布等主要操作使用底部粘性操作栏。

## 8. 容器查询与内容适应

- 可复用卡片优先根据容器宽度切换横排/竖排，不只依赖视口。
- 标题使用可控换行与`overflow-wrap:anywhere`处理长链接和英文。
- 图片容器预留宽高比，使用`object-fit:cover`。
- 动态高度内容不能依赖固定像素高度截断重要信息。
- 200%浏览器缩放下仍可完成导航、表单与阅读。

## 9. 安全区域与输入设备

- 底部导航和抽屉使用`env(safe-area-inset-bottom)`。
- 鼠标悬停效果必须有键盘焦点和触控反馈等价状态。
- `hover:hover`时才启用倾斜、跟随或悬停位移。
- 触控设备不显示必须点击才能消失的悬停提示。
