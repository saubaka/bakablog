## 第二阶段必须处理的既有问题

正常动效下，部分长卡片（首次向导尤为明显）的顶部轮廓在 settled 后仍有闭合缺口。现有 `configureMotionOutline()` 使用正在缩放的 `getBoundingClientRect()` 建立 viewBox，同时 path 使用 `non-scaling-stroke`；恢复尺寸后视觉周长与 dash 长度不一致。采样证明 path 的存储长度与 `getTotalLength()` 相等、offset 为 0，但这不足以证明屏幕上的轮廓已经闭合。

证据为 `normal-motion-setup-known-gap.png`。这不是第一阶段新增运动系统导致的问题，本轮没有用第二条 CSS 边框掩盖缺口。第二阶段应在未变换的局部几何中计算轮廓，再验证缩放、圆角、滚动重入与结束帧，确保单个轮廓完整闭合；同时补充探针，防止只检查“存在一个 path”就误报视觉完成。

顶部通知、弹窗体验仍待第三阶段；增强导航与刷新连续性待第四阶段；后台预览及全站长尾待第五阶段，整体收尾待第六阶段。
