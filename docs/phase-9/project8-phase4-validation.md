# 项目8移植第四阶段：增强导航与页面切换

日期：2026-10-09。应用版本：Cloudtrace 1.40.0。

## 实施范围

只改当前项目1及其内部bakagit；源项目8只读，多用户版不改。首选端口5010、正式数据库与管理员状态不变。第五阶段（通知分类型参数、预设与revision保存，以及长尾页面覆盖）没有提前实施。

## 已完成

- **同壳导航**：新增`app/static/scripts/page-navigation.js`。点击同源的普通GET链接或提交GET表单时，脚本先在后台请求目标页面，旧页面保持显示；拿到新HTML后只替换页面区域，导航栏、后台侧栏、通知宿主和全局弹窗都保留。前台替换`<main data-navigation-region="site">`，后台替换`.admin-workspace[data-navigation-region="admin"]`（顶栏标题、操作按钮和正文）。
- **切换节奏**：旧区域淡到60%并下移4px（150ms），新区域从下方8px淡入（300ms）。请求超过140ms时，页面顶部出现一条浅蓝进度线，请求结束后消失。动画时长和请求时长分别记录：本机隔离实例上请求约7–14ms，切换约160ms。
- **什么情况下会退回普通跳转**：以下任一情况都改用浏览器原生跳转，原有遮罩过渡照常播放：
  - 非2xx响应、返回的不是HTML、跨域或跨协议；
  - 外壳指纹不一致，包括菜单、品牌、后台侧栏、主题设置、脚本或样式资源中任何一项变化；
  - 目标页标记为`native`（文章编辑器和独立页面编辑器）；
  - 路径在原生名单里，包括登录`/bakaadmin`、`/auth/`、`/out/`、媒体文件、订阅源和健康检查；
  - 带`data-navigation="native"`、`data-no-transition`的链接，以及图片预览、弹窗触发和外链放行链接；
  - 页面区域缺失或请求出错。
  
  登录过期时服务器会重定向到`/bakaadmin`，这一步也走原生跳转，权限仍由服务器校验。
- **外壳指纹**：服务端新增`shell_digest`过滤器，对导航栏、页脚、移动底栏、抽屉和后台侧栏的HTML计算指纹。计算时忽略`is-current`、`is-open`、`aria-current`、`aria-expanded`和CSRF值。`<html>`上的主题属性另有`data-theme-signature`；两页的指纹或head中的脚本、样式列表只要不一致，就不替换区域。
- **安全**：新HTML只用`DOMParser`解析。插入前删除区域内除`application/json`以外的所有`<script>`，不执行抓取到的脚本，也不使用`innerHTML`或`eval`。新请求会取消旧请求，过期响应不会覆盖新页面；请求使用`cache: 'no-store'`，内存和本地存储里都不缓存页面。
- **历史、滚动与焦点**：前进使用`pushState`，在当前地址重复点击使用`replaceState`。离开页面前把滚动位置写进history state，后退/前进时恢复（`scrollRestoration = manual`）；跨文档返回时由首次加载读取state恢复。目标带锚点时滚动到锚点，否则回到顶部。替换后焦点移到`#main-content`。同步更新标题、description、keywords、robots、author、canonical、alternate、OG/Twitter标签和JSON-LD，以及页面级body类（如`search-body`）。
- **导航状态同步**：按`href`同步桌面胶囊、移动底栏、抽屉和后台侧栏的当前项（每个容器单独计算），移动端“更多”按钮也同步。桌面当前项指示器和移动底栏指示器会移到新位置，胶囊显隐状态重置。后台母菜单展开新页面所属的分组。导航开始前自动关闭移动抽屉和后台抽屉。
- **模块生命周期**：页面级代码改为`CloudtracePage.define(name, init(scope, signal))`。首次加载时在整个文档上运行一次，之后每次换页先卸载（abort加cleanup），再只在新区域上重新挂载。`app.js`拆出14个模块，另外`search.js`（改为全局加载）、`ui-global.js`表单、`site-management.js`编辑器和`human-check.js`也已接入。具体处理：
  - 更新中心和系统状态页的轮询、本地时间计时器、阅读进度的window监听与ResizeObserver、计数器观察器、自动保存计时器和搜索请求都在离开时清理；
  - 主题设置页未保存的实时预览会在离开时恢复`<html>`的样式、data属性和后台菜单紧凑状态；
  - 动效运行时新增`CloudtraceMotion.prepare(scope)`，换入的区域与首次加载得到同样的入场准备。
- **未保存保护**：页面区域内的POST表单只要有真实的用户输入（`isTrusted`）就标记为已修改，提交后清除。此时离开（包括后退）会弹出主题确认框；取消会留在原页且草稿不丢，确认后才离开。走原生跳转的链接同样先确认。编辑器页面仍使用原有的`beforeunload`保护。
- **保留的行为**：规划第8.1节提到的“累计滚动约32px隐藏、18px显示”，与2026-07-26你明确要求的“任意小幅滚动立即隐藏或出现”冲突，而且已有契约测试锁定后者，所以本轮保留你之前的要求，只在换页后重置滚动记录。底部抽屉保持现有的底部弹出形式，换页时自动关闭。

## 验证

- 完整pytest：215 passed，另有23条既有的SQLite日期警告。新增`tests/test_page_navigation.py`，覆盖：前台9个页面共用一个外壳与主题指纹（搜索页的body类单独记录）；后台5个页面共用一个指纹，编辑器页面标记为`native`；指纹会忽略当前项和CSRF，但能区分真实链接变化；导航运行时的安全与生命周期契约。Ruff、compileall、9个前端脚本的语法检查都通过；四份CSS解析错误为0。
- 第四阶段专项浏览器脚本在1280×900、768×1024、390×844三种尺寸下各跑11个场景，全部通过：
  1. 首页到博客没有整页刷新，导航当前项、焦点和区域数量都正确；1.8秒后可见卡片的轮廓全部画完。
  2. 博客到文章后阅读进度重新生效。
  3. 文章到搜索后搜索功能可用，body类随页面切换。
  4. 后退回到文章，滚动位置与离开时一致；前进也不会刷新整页。多次换页后的动效注册数与全新加载一致，没有泄漏。
  5. 快速连点三个菜单，只显示最后一个目标页面。
  6. 人为延迟1.5秒的慢请求期间，旧页面仍可读，顶部显示进度线。
  7. 访问不存在的文章（404）时退回整页加载。
  8. 留言写了一半时离开会弹出确认；取消后草稿保留，确认后才离开。
  9. 后台从文章列表进入编辑器（原生跳转），再进入设置页；设置页未保存的预览在离开时被恢复，动画预览模块可以正常使用。
  10. 离开系统状态页后，资源轮询停止。
  11. 清空Cookie后点击后台菜单，由服务器重定向到登录页。
  
  除第7步故意访问不存在的页面产生的两条404外，控制台没有其他错误。
- 完整`visual_probe.js`以exit 0结束：9组动效样本、39个三端公开页面状态、120个三端后台状态，并包含首帧、轮廓生命周期、编辑器菜单、移动胶囊和滚动回入检查，各项问题均为0。
- 证据目录为`session-data/qa/v1.40.0-project8-phase4`：其中有`phase4-report.json`（含每次切换的请求和动画耗时、泄漏对比、轮询计数）、`probe/report.json`，以及三端的博客、轮廓画完后、慢网加载、未保存确认和后台列表截图。

## 验收与发布边界

项目要求的verify-web-visuals Skill在当前环境里不存在，本轮改用Playwright专项脚本和完整探针完成同等检查。应用内浏览器窗格本轮处于隐藏状态，浏览器会暂停动画和观察器，不适合做交互验收，因此交互验收都在可见的Playwright Chromium中完成，没有把隐藏窗格里的结果当作证据。

验收使用了两个临时实例：5019是带测试数据和测试管理员的实例，5029是空站点向导实例，两者都位于会话临时目录，随机密码不落盘到仓库。没有修改正式数据库、没有推送或发布。

尚未覆盖的部分：
- 文章和独立页面编辑器本身仍走原生跳转。编辑器把脚本改造成可重复挂载，以及草稿与`beforeunload`的接管，需要单独评估。
- 规划中“独立浮动子菜单”的视觉改造没有做；本轮只保证现有抽屉在换页时正确关闭。
- 性能数据只来自本机隔离实例，不代表真实网络或其他设备。
