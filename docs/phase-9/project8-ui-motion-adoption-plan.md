# 项目 8 视觉与动效完整移植规划

日期：2026-10-01（2026-10-10更新）。状态：项目 1 第一至六阶段已全部实施并验收（1.42.0）。

源项目：同级 `8`（BakaMail），仅供只读参照。用户已明确本次修改目标为当前目录 `1` 个人版及其内部 `bakagit`，不修改 `1-multiuser`。项目 1 当前版本为 Cloudtrace 1.41.0，首选端口仍为 5010；相邻项目的代码、端口与数据均不在本次范围。

## 一、移植目标与边界

将项目 8 当前实际生效的配色、材质、字体、控件、导航反馈、卡片运动、顶部通知和弹窗体验应用到博客的前台与后台。不是只换首页，也不是在旧样式之后继续堆积覆盖。

移植视觉系统与交互机制，不移植邮箱业务、BakaMail 品牌、邮件演示文案、邮箱协议、Node 服务或 Vue 框架。保持 Flask、Jinja2、SQLAlchemy、SQLite、本地静态资源和现有部署方案。个人版不重新增加用户中心、注册或普通用户功能；本次不操作多用户版。

保留站点文章、动态、项目、相册、友链、留言、独立页面、编辑器、上传裁剪、SEO、安全设置、管理员创建向导和更新管理。不要因为源项目存在某个模块，就在博客增加无关模块。

保留现有后台可修改的视觉偏好；改换默认值应有兼容迁移，不把用户存过的参数静默重置。此前删除的右下角动效切换按钮不重新出现。

## 二、解析依据：必须以最后生效的样式为准

### 2.1 源码入口与覆盖顺序

项目 8 的入口为 `web/src/main.ts`、`web/src/App.vue`。实际加载链先引入项目 1 的 vendor 样式，然后引入邮件各模块样式，最后由 `local-theme.css` 与 `dashed-accent.css` 收束外观。

主要核对文件：

| 层级 | 源文件 | 解析重点 |
| --- | --- | --- |
| 基础与最终样式 | `web/src/styles/local-theme.css`、`dashed-accent.css` | 最终颜色、按钮底色、轮廓、阴影 |
| 页面与布局 | `intro.css`、`login.css`、`workspace.css`、`admin.css`、`reader.css` | 排版、密度、桌面/手机布局 |
| 控件与浮层 | `dialogs.css`、`notifications.css`、`theme-controls.css`、`search-motion.css` | 弹窗、通知、切换、搜索 |
| 通用运动 | `web/src/motion.ts`、`surfaceLines.ts`、`pressFeedback.ts` | 描边几何、进退场、按压、资源清理 |
| 通知状态机 | `web/src/notifications.ts`、`notificationTiming.ts`、`notificationConfig.ts`、`shared/notificationMotion.ts` | 替换、堆叠、计时、配置 |
| 配置与组件 | `NotificationAppearance.vue`、`LineOutline.vue`、对话框组件 | 参数范围、预览、弹层生命周期 |

`web/src/styles/app.css` 不是本次入口实际加载的最终权威，不能根据这个大型文件单独推断项目 8 的当前外观。

### 2.2 三个容易误判的事实

1. 文件名虽然包含 dashed，最终可见轮廓实际上是浅蓝实线，不是虚线。
2. 主按钮的早期规则存在浅蓝填充，但最终覆盖后实际是白底、浅蓝轮廓；选中项也不是大块蓝色填充。
3. 项目 8 的运动主要是 WAAPI/CSS 时间曲线，不是完整的物理弹簧求解。描边代码保留 `strokeDashoffset`，但最终 CSS 取消了虚线参数，因此当前实际表现不能称为完整的单线轨迹描绘。

本次移植优先复现可见外观与交互节奏，不把未实际生效的源码规则当成验收目标。目标博客已有单线物理系统，后续要统一为一个运行时，不能再叠一套源项目动画造成双描边、双缩放。

### 2.3 本轮实际页面检查

使用应用内浏览器与项目 8 自带的隔离 fixture，未访问真实邮箱数据。检查了工作区、通知堆叠、确认弹窗、后台通知设置与入口页：

- 桌面 1280×900：实际确认白底主按钮、浅蓝实线轮廓、顶部中央通知和入口组合排版。
- 平板 768×1024：检查后台通知参数布局和表单适配。
- 手机 390×844：检查工作区与底部胶囊、通知宽度。
- 抽查状态没有文档级横向溢出；检查到的控制台警告/错误为空。

这些是源项目抽样解析证据，不是目标博客改造后的完整验收，更不是线上邮件服务验收。项目 8 既有测试报告仅供参考，本轮未重新运行其完整测试集。

错误、警告、成功保留独立语义色和文字/图标。项目 8 的成功通知圆点并不是必然绿色；移植默认可沿用浅蓝主题，错误与警告仍须一眼区分。既有自定义颜色应继续可编辑。

### 3.2 表面规则

- 页面背景平整；内容卡片以白底、极淡线条和小阴影为主。
- 选中项使用白底与强调轮廓，避免大面积蓝色块覆盖内容。
- 主操作、次操作保持层级，不能因为都白底就无法识别；通过文字、边缘、尺寸与语义图标区分。
- 可点击卡片有轻量悬停反馈；非交互内容卡片不做夸张漂浮。
- 玻璃模糊仅用于浮动导航和必要的工具栏。内容表面不持续做大面积 backdrop-filter。
- 装饰背景与信息卡片分离；首页不增加白色的大包裹区域。
- 一个组件只能有一个描边所有者。动态 SVG 工作期间不能同时显示完整 CSS border；动画结束仍有稳定轮廓，不能消失。

### 3.3 圆角、阴影与字体

| 对象 | 基准圆角 |
| --- | --- |
| 小标签 | 9px |
| 按钮、输入、列表行 | 13–14px |
| 普通卡片 | 20px |
| 大容器 | 28–30px |
| 弹窗 | 22px |
| 顶部通知、底部胶囊 | 28px |
| 浮动菜单、选项 | 16–24px / 9px |

阴影基准：小阴影 `0 1px 2px rgba(53,64,82,.045)`；普通 `0 9px 24px rgba(70,91,122,.07)`；浮层 `0 24px 58px rgba(70,91,122,.15)`。更大的阴影只用于更高层级，不给每张卡片添加厚重阴影。

字体采用源项目温和的系统字体链：`ui-rounded, Microsoft YaHei UI, PingFang SC, Noto Sans CJK SC, system-ui, -apple-system, sans-serif`，继续支持项目已有本地字体选择，不引入在线字体。正文约 16px，界面行高约 1.5–1.65；文章长文保留约 1.8。控件 13–14px，辅助信息 12px 左右。数值启用等宽数字。

源项目入口的大标题可达 44–68px，但这不是后台或手机文章标题的统一标准。博客应保持内容标题与界面标题分级，手机大标题以 30–36px 为主要范围，具体长标题要实测。

内容容器约 1160–1280px；文章正文约 680–740px。间距优先使用 4/8/12/16/24/32/48/72px，避免任意不同的卡片间隔。所有网格列使用 `minmax(0, 1fr)`，子项 `min-width: 0`，长网址可断行，保存操作靠右且垂直居中。

## 五、通用运动：时序、描边与性能

### 5.1 项目 8 当前运动参数

| 类型 | 源项目基准 | 实际机制 |
| --- | --- | --- |
| 展示/普通卡片 | 620 / 500ms | 透明度、8px 位移、轻微缩放同步进入 |
| 控件 | 360ms | 更短的进入反馈 |
| 普通按压 | 360ms | 1 → .965 → 1.015 → 1 |
| 提交按压 | 240ms | .978 下移 → 1.008 轻回弹 → 稳定 |
| 悬停 | 180–260ms | 少量上移、边缘与阴影调整 |
| 页面进入/离开 | 约 460 / 150–180ms | 淡入、短位移，不等长阻塞 |
| 工作区内部切换 | 220–300ms | 横向约 18px、淡入、最多 2px 模糊 |
| 轮廓反馈 | 420ms，退出约 200ms | 浅蓝边缘浮现，局部轻微位移 |
| 滚动列表回入 | 约 340ms | 12px 内位移、淡入、轻模糊 |
| 搜索展开/收缩 | 约 220ms | 内容高度变化与透明度协调 |

时间曲线主要为 `cubic-bezier(.2,.78,.22,1)` 或相近柔和曲线。不是强弹跳，也不是始终匀速。

### 5.2 描边取舍必须明确

项目 8 有两类代码：通用运动使用一个圆角 rect；浮层/选择轮廓使用四个裁切的边缘片段。最终全部表现为实线。四片段不能成为博客所有卡片的默认方案，否则会重新引入接缝、双线与圆角不规律的问题。

建议统一规则：

1. 常规卡片与按钮使用一个与实际圆角同步的轮廓；不复制四段描边到每个嵌套组件。
2. 仅导航选择、弹窗等确实需要源项目轻微边缘反馈的场景，使用专用且经过圆角验收的轮廓层。
3. 轮廓坐标依据 ResizeObserver 测量；图片加载、字体切换、窗口变更、表单展开后更新。
4. 一次出现只运行一套动画，不同时保留旧描线、新描线与原有 border。
5. 如继续保留博客的物理轨迹表现，由原有物理求解器输出同样的视觉幅度与时长；这属于实现适配，不声称源项目本身有相同物理算法。
6. 本规划以项目 8 最终可见节奏为主，不继续沿用旧规划中长时间逐层等待的默认效果，避免卡片先空白等待描线。

### 5.3 生命周期与滚动

源项目使用 IntersectionObserver、ResizeObserver 和 WAAPI；动画播放过程中可反向，不必排队完成后再退出。目标建立统一初始化/销毁入口，共享观察器与缓存，不为每个嵌套按钮重复建立长链观察器。

- 首屏直接可见的内容必须有默认可读状态，JS 失败不能导致全页透明。
- 真正离开视区的元素才退出；保持可见的元素不能滚一格就重播。
- 列表内部滚动以对应滚动容器为 root，而不是统一监听 window。
- 聚焦元素不因滚动动画被隐藏，避免键盘用户失去位置。
- 快速滚动、连续点击、改变方向时续播或取消，不重置到初始帧。
- 首屏分组错开几十毫秒，最多约 120ms，不把十几张卡片串成数秒长队列。
- 减少动态模式取消位移、缩放、模糊与水滴落下，保留立即可见的状态反馈；运行中切换也要正确完成正在进行的状态机。

`will-change` 只在动画期间使用，结束清理。模糊限制在局部、短时；不用全页大范围滤镜遮盖网络等待。持续运动优先 transform/opacity，高度仅用于必须真实重排的菜单与结果区，读写布局分帧。

## 六、顶部通知完整规格

### 6.1 外观与位置

从当前右下角提示迁移为顶部中央胶囊。顶部至少 16px，并计入安全区；宽度依据内容自适应，约 250–340px，始终不超过视口减 32px。白底、1px `#BED8EF` 轮廓、28px 圆角、小阴影。正文约 13px、行高 1.55；状态点约 7px；关闭按钮约 32px 且为圆形；可选操作按钮不挤压正文。

长标题、长网址与动作文本必须换行；不通过无限缩小文字解决溢出。移动端不侵占底部导航，也不遮挡裁剪面板关键操作。

通知壳本身使用稳定 CSS 实线边框，不用每帧测量的 SVG 给水滴变形描边，以免形状变化时出现丢线和几何竞争。

### 6.2 进入、替换与退出

默认入场 780ms：窄水滴从上方约 70px 出现，落到当前位置，经历圆形短暂缓冲，扩展为完整胶囊。文字在动画约 80% 后进入，结束时内容完整。不是通知卡片一出现就全部可读，然后再叠一个轮廓动画。

默认退场 680ms：文字先淡出，胶囊收为圆形，再变为水滴向屏幕下方离开。通知宿主是固定、独立的容器，不撑开页面布局，不产生横向滚动。

同一个操作从“处理中”变为“成功/失败”时，复用同一个胶囊，只更新文字与语义状态：文字退出约 160ms、进入约 340ms，带最多 6px 短时模糊和小位移；不再播放第二颗水滴。

### 6.3 堆叠和交互

- 最新通知在前；最多同时呈现前景加三个背景层，背景每层下移约 9px，缩放差约 .015。
- 背景层仍是白底；深层内容隐藏且不可交互，不存在透明但能点击的按钮。
- 点击空白壳或 Enter/Space 可循环前景；关闭按钮只关闭目标；Escape 关闭当前。
- 多条消息采用当前最宽通知的宽度，避免每次轮换左右抖动。
- 连续洪泛需要逻辑队列上限与合并策略；这是对源项目的防护补全，不是已经存在的源项目能力。
- 关闭、轮换、替换动画可以中断，不创建并行状态机。

### 6.4 停留时间与安全行为

入场时间、退场时间与停留时间必须分开。普通通知按内容长度停留，源项目约 5.2–14 秒；错误和处理中的通知保留，直到用户关闭或操作完成。完成后的进度通知可短暂停留约 3.2 秒。鼠标悬停、焦点进入、页面失焦/隐藏时暂停计时，不在后台标签页悄悄消失。

保留 `role=status` / 适度 `aria-live`，错误可用 alert，避免加载每一帧读屏播报。使用 textContent，禁止把后端报错作为 HTML 注入。

原生 dialog 的顶层会覆盖普通页面通知，因此通知宿主要能在活动 dialog 顶层内正确显示；关闭后归还宿主，不能为显示通知而破坏模态 inert 或焦点陷阱。

使用 animationend 完成状态，带短超时兜底；0ms、reduced-motion、重新打开、切换路由和 AbortSignal 都必须立即且正确清理。

### 6.5 管理面板参数与预览

放在现有“主题 → 弹窗与通知”对应内容区，不新建一串重复菜单。五种类型：成功、信息、警告、错误、处理中。每种可设置：进入、退出、文字退出、文字进入；另设全局堆叠过渡时间。

| 参数 | 默认 | 范围 |
| --- | --- | --- |
| 进入 | 780ms | 0–3000ms |
| 退出 | 680ms | 0–3000ms |
| 文字退出 | 160ms | 0–1000ms |
| 文字进入 | 340ms | 0–1000ms |
| 堆叠 | 320ms | 0–1500ms |

提供快速/标准/舒缓预设。预览包括五种类型、长文、带动作、多条堆叠、处理中转成功/失败、关闭全部。预览使用草稿快照，退出配置页要取消其任务，不能更改正式配置。

颜色、圆角等沿用当前后台已有设置项并映射到新组件，删除无法实际生效的旧参数。保留旧停留时间的含义，不能把原 `toast_duration` 当成水滴入场时间。

服务端用现有 SQLite 设置存储，统一 schema/revision、校验范围和原子保存。请求带 CSRF 与版本号，冲突保留草稿并提示重新读取；读取失败不能把默认配置误存为正式配置。配置随初始 HTML 提供，增强导航时可用带 ETag 的轻量端点；失败使用本地默认，不陷入“获取通知配置失败又弹通知”的循环。

## 七、弹窗、浮层与表单

优先保留原生 dialog 的可访问能力，再应用主题表面：白底、浅蓝实线、22px 圆角、轻阴影，宽度通常约 510px，桌面 padding 24px、手机约 20px。可视尺寸始终扣除视口边距与安全区；图片编辑等大内容使用专用尺寸，不硬塞普通确认框。

显示使用轻微缩放、小位移和淡入，轮廓与表面协调；退出约 200–260ms。直到退出完成才解除模态，不能先放开背景点击。重新打开或快速关闭时取消旧计时器，避免新弹窗被上一轮关闭任务关闭。

正文只保留必要标题、内容和操作，禁止重新加入“温柔确认”“请谨慎确认”等装饰说明。删除确认明确对象与风险；输入确认保留标签与错误信息。默认焦点和关闭后焦点恢复必须正确。确认/取消/保存靠右排列，手机必要时换行但不溢出。

自建 select、分段菜单、数值步进、开关、圆形选择按钮继续全站统一，包括编辑器、发布状态和管理员设置。每个控件覆盖默认、hover、active、focus-visible、disabled、busy、success、error，不只修改正常态。

## 八、导航与无卡顿页面切换

### 8.1 样式与滚动逻辑

桌面后台保留现有母/子菜单结构与功能命名，采用源项目的白底轮廓选择与一致字级。不要为每个菜单层额外增加渐变。仅一个同级分组展开；子菜单浮层独立，不扩大整个胶囊。

桌面与手机浮动导航继续使用滚动意图判定：顶部附近或内容不足时显示；向下累计约 32px 隐藏，向上约 18px 显示；极小位移不反复触发，切换滚动容器时重置累计值。临近底部约 16px 可保持入口可达。采用实际滚动容器，不把页面、预览与内部列表的滚动混为一谈。

底部胶囊约 28px 圆角、轻轮廓，计入 safe-area。源项目进入约 360ms，形状从窄胶囊轻微展开并小回弹；退出约 300ms。独立子菜单进入约 360ms、退出约 240ms；点击子项、外部、滚动或导航后关闭。当前项轮廓追随实际尺寸变化，文字真正垂直居中，不只移动视觉色块。

### 8.2 为什么不能只复制源项目路由动画

项目 8 使用 Vue 内部导航，工作区 shell 可持续存在；目标博客主要是 Flask 整页返回。整页卸载、重新解析 CSS/JS 与重建状态产生的停顿，不会因为多加一段淡入动画而消失。

需要为已知的同源 GET 页面引入渐进增强导航：

1. 保留公共 shell、菜单与通知宿主；点击菜单时请求目标 HTML，只替换约定主体区域。
2. 请求期间当前页保留，不先把整页变透明；准备好新内容后完成小幅切换。
3. URL、title、meta、页面配置、当前导航项同步；history/back/forward 与滚动恢复正确。
4. 每个模块有 init/dispose：编辑器、搜索、选择器、裁剪、上传与动效不重复绑定。
5. 只拦截明确支持的同源 GET；下载、外链、登录、初始化、POST、上传提交默认保持原流程。失败退回原生导航。
6. 新请求取消旧请求，过期响应不得覆盖新页。后台和私密页面不跨用户缓存、不写共享持久缓存。
7. 未保存编辑触发现有主题确认；取消不跳转，确认后清理。不能为了流畅丢弃草稿。
8. 不执行抓取 HTML 中任意脚本；通过明确注册模块与配置刷新，不引入通用 eval。

可用浏览器 View Transition 作为额外增强，但不能把兼容性有限的能力作为唯一实现。安全与业务行为不为过渡效果让路。

### 第一阶段：主题基线与基础表面

**任务**：建立源项目最终规则清单；提取 token 与字体、间距、圆角、阴影；统一页面背景、卡片、表单基础、标题层级；清理双重描边与高优先级冲突。先让首页、文章列表、后台仪表盘、设置表单和初始化页具有一致静态外观。

**交付**：统一主题权威层、控件状态基线、旧规则映射表；项目 1 与内部镜像同步。1.37.0 已实施，详见 [第一阶段验收](project8-phase1-validation.md)。

**验收**：三端截图对照；白底/浅蓝轮廓真实生效；没有大面积彩色填充、巨大包裹白块、默认浏览器样式或保存按钮错位；关闭动画也可完整阅读。

**交付**：统一 motion 生命周期、配置适配与可复用控件，文章/项目/动态卡片与后台列表先覆盖。1.38.0 已实施，详见 [第二阶段验收](project8-phase2-validation.md)。

**验收**：每组件恰好一个轮廓所有者；结束仍有边缘；无四角接缝、双线、内容长时间空白；多次滚动回入不闪烁；减少动态即时生效；页面离开后观察器、动画、will-change 清理。

**验收**：保存、上传、复制、失败与更新状态真实可用；长文/带动作不溢出；处理中转完成只更新同一个壳；失焦不丢消息；连点关闭、0ms、减少动态、弹窗内通知均无残留或点击穿透。

### 第四阶段：导航与页面切换去刷新卡顿

**任务**：先建立受支持 GET 页面的 shell/主体边界和模块生命周期，再接入增强导航；保留旧页直到响应准备好；同步历史与导航选择；适配桌面侧栏、顶部胶囊、移动底栏、独立浮动子菜单与滚动意图。

**交付**：普通菜单跳转在同一 shell 内完成，视觉节奏与源项目接近；未支持页面自动原生跳转且仍有安全的入场反馈。1.40.0 已实施，详见 [第四阶段验收](project8-phase4-validation.md)；滚动显隐保留用户此前明确要求的“任意滚动立即响应”，未改为累计阈值。

**边界**：提交、安装更新等长任务不伪装成普通路由；接口等待与动画时间分别报告，不用动画遮掩服务器慢请求。

## 十二、主要风险及处理

1. **复制整个源样式导致覆盖混乱**：只提炼最终规则与必要组件，旧样式逐项退役。
2. **“描线”与实际实线效果混淆**：以最终可见表现验收，动画轨迹若保留必须单独明确并测试。
3. **两套动画运行时叠加**：统一所有权、初始化与销毁；每个元素最多一个主编排。
4. **Flask 刷新停顿仍在**：专门实施渐进增强导航，不只增加淡入。
5. **通知被弹窗压住或提前消失**：顶层宿主、前景计时、焦点与退场状态联合测试。
6. **源项目出现的装饰标签污染博客**：不迁移邮箱品牌和无关提示，仅迁移规则。
7. **跨版本配置丢失**：显式 schema/revision 与旧参数映射，读取失败禁止覆盖。
8. **误改相邻项目**：只操作当前项目1与内部bakagit；不整体复制应用或数据库，不修改源项目8与多用户版。
