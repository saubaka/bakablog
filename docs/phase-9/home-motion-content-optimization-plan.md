# Cloudtrace 首页动效与内容去模板化实施方案

更新日期：2026-09-13  
基线版本：1.34.23  
实施状态：第一阶段已于1.34.24完成；第二阶段已于1.34.25完成；第三阶段已于1.34.26完成。

## 一、现场结论

### 1. 线条覆盖并不完整

- 当前首页实际有15个内容卡片，页面DOM合计16个`.card`与19个`.button`。
- 16个卡片成为线条目标，但19个按钮中没有任何一个成为线条目标；按钮只能看到普通边框和悬停反馈。
- 目标由“所有`data-reveal`与`.card`，再排除包含子卡片或子`data-reveal`的节点”推导。这个隐式规则会随内容数量和嵌套结构变化，同一种组件在空状态、已有内容和弹窗状态下可能得到不同结果。
- 后插入的卡片只会补`.is-revealed`，不会创建SVG轮廓、计算路径和加入观察器；弹窗、异步结果、编辑器动态面板因此可能没有线条动画。
- 隐藏状态下宽高为0的卡片无法建立路径，目前没有完整的“显示后再初始化”流程。

### 2. 滚动监听存在，但触发位置不符合视觉预期

- 当前`IntersectionObserver`使用`threshold:0`与上下各缩小8%的观察区域。元素只露出一条边时就开始620ms入场，用户真正看到主体时动画可能已经结束。
- 出场必须等元素完全离开观察区域才会触发，动画发生在屏幕外，所以用户看不到“随滚动退出”。
- `back_forward`恢复会直接进入`skipScrollReveal`，所有卡片立即完成且不再注册滚动观察器；从浏览器返回首页后，滚动动效完全失效。
- 所有首页目标一律`motionPersist=true`，没有区分首屏、长卡片、短卡片、操作控件和动态浮层。

### 3. 页面转场会遮住卡片动画

- 默认页面转场为720ms拉伸覆盖，包含全屏渐变幕布、亮条、主内容裁切和位移。
- 卡片的620ms线条动画在页面转场尚未结束时已经开始，两套动画并发。线条可能在幕布后绘制完毕，用户看到页面时只剩完成态。
- 页面转场、卡片线条、文字模糊、卡片悬浮、`data-tilt`和按钮弹性使用不同缓动，形成明显的“动画展示模板”感。

### 4. 首页结构和文案存在重复模板感

- 桌面首页渲染8个模块、15张卡片；关于区域单独使用6张卡片。移动端页面长度超过4600px，大量内容是空状态。
- 每个区块几乎都重复“眉题 + 大标题 + 一句诗性说明 + 右侧箭头 + 白色圆角卡片”，缺乏不同内容类型应有的信息结构。
- “最近”“小小”“星球”“这里”“此刻”等词反复出现；`ONLINE`、`FAVORITE TOOLS`、胶带、闪光、星球轨道、虚线标签同时使用，装饰主题过多。
- 目前文章数据为标题`11`、摘要`111`。这是用户数据，实施时不能静默删除或覆盖；应在后台提供内容质量提示，前台则避免将明显测试内容放大为首页视觉中心。
- `stats`模块仍在数据库中启用，但首页模板没有对应渲染分支，属于无效配置。

## 二、实施原则

1. 边界永远可靠：无JS、路径未初始化、动态内容、减少动态效果和低性能模式下，都必须保留普通静态边框。
2. 动画只表达状态：入场说明“内容进入阅读范围”，出场说明“内容离开当前阅读段落”，不把每张卡片做成动画演示。
3. 同一时刻只保留一个主动画：页面转场结束后才允许首屏卡片入场；悬停和按压不覆盖入场所使用的transform。
4. 不再依赖DOM嵌套猜测组件类型；模板必须明确声明哪些是布局壳、内容表面和操作控件。
5. 先让首页内容真实、紧凑，再做动效。空数据不能靠巨大占位卡片填满页面。

## 三、第一阶段：修复线条覆盖与滚动状态机

### 1. 建立显式目标协议

新增三类模板标记：

- `data-motion-surface="feature"`：精选文章、项目主卡、关于主块等主要内容卡片。
- `data-motion-surface="compact"`：状态块、小型资料块、空状态和列表项。
- `data-motion-control`：需要线条入场的按钮、图标按钮和胶囊控件。
- `data-motion-shell`：纯布局容器，永远不创建轮廓，也不隐藏内容。

删除“包含子`.card`或`data-reveal`就排除”的隐式判定。模板自己声明角色，使空状态、已有内容和动态插入状态保持一致。

### 2. 让静态边框成为可靠后备

- 所有卡片和按钮默认显示主题静态边框。
- 只有SVG路径已生成、长度大于0并写入尺寸后，才添加`is-outline-ready`并隐藏对应静态边框。
- 完成态由SVG保留最终边缘；路径丢失、组件隐藏、脚本失败或切换减少动态效果时立即恢复CSS边框。
- ResizeObserver只在尺寸真正变化时重算，不在动画帧中反复读取布局。

### 3. 重构统一注册器

建立`registerMotionTarget(element)`：

- 初始页面和MutationObserver新增节点都走同一个入口。
- 目标宽高为0时先保留静态边框，等`ResizeObserver`或首次显示后再建路径。
- 重复注册必须幂等，不增加第二个SVG或第二个观察器。
- 节点删除时取消动画、观察器和缓存，避免WeakMap之外的监听残留。

### 4. 改为可见比例与方向共同驱动

保留单一IntersectionObserver，但使用`[0, .08, .16, .28, .5]`阈值并计算：

`可见比例 = 可见像素高度 / min(元素高度, 视口有效高度)`。

建议状态规则：

- 首次进入：可见比例达到16%且元素正在进入阅读区时开始。
- 向下离开：元素上移且可见比例降到12%时开始退出，此时屏幕上仍看得到末段。
- 向上离开：元素下移且可见比例降到12%时对称退出。
- 12%与16%之间保持原状态，形成迟滞区，避免边界抖动。
- 快速滚动直接改变现有WAAPI的`playbackRate`，从当前进度反向或继续，不创建排队动画。
- 高于视口的长卡片按“有效可见高度”计算，避免永远达不到阈值。

删除`back_forward`直接跳过观察器的逻辑。BFCache恢复时读取当前位置，先同步当前可见状态，再重新观察所有目标。

### 5. 协调页面转场

- 页面进入期间只准备轮廓，不播放卡片动画。
- 页面转场完成后发出`cloudtrace:page-ready`事件，再启动当前视口内的卡片。
- 首屏只允许主介绍卡和状态块最多相差60ms，不做整页瀑布式延迟。
- 通过页面内锚点、浏览器返回或恢复滚动位置时，不重播整页转场，只同步当前位置的卡片状态。

## 四、第二阶段：降低线条和卡片动画的AI感

### 1. 动效分级

| 类型 | 线条 | 内容 | 时长 |
| --- | --- | --- | --- |
| 主要内容卡片 | 保留“上方中心向左右、沿边缘向下、下方中心汇合” | 4px位移、0至1透明度、最多1.25px短暂模糊 | 420–480ms |
| 紧凑卡片 | 同一路径但线条颜色变化更轻，不出现起点光点 | 3px位移与透明度，不模糊 | 300–360ms |
| 按钮和胶囊 | 短轮廓绘制，完成后保持静态边线 | 只做透明度，不移动文字 | 180–220ms |
| 布局壳与区块标题 | 不画外框 | 4px以内淡入 | 220–280ms |

### 2. 删除会强化模板感的动作

- 删除卡片`data-tilt`透视跟随；可点击卡片悬停最多上移1px。
- 卡片、按钮悬停不再使用超调spring；统一使用`cubic-bezier(.2,.7,.2,1)`。
- 按下状态使用`translateY(1px)`与极轻阴影收紧，不再同时缩放到`.975`。
- 删除线条起点的明显发光圆点；改为1px短线或直接从中心无装饰展开。
- 大面积内容不使用3px持续模糊。只有主要卡片文字在前40%进度使用不超过1.25px模糊。
- 页面转场默认不再使用全屏渐变亮条。保留管理面板中的动画选项，但将前台默认改为短淡入或克制的单向揭示，并确保不与卡片动画重叠。

### 3. 性能边界

- 动画期间只提升正在移动的1至3个元素，完成后清除`will-change`。
- 每张卡片只动画一个内容包装层，不给每个标题、段落和按钮分别创建WAAPI实例。
- 线条只更新`stroke-dashoffset`；内容只更新`transform/opacity`，主要卡片才短暂使用低半径filter。
- 同一帧集中读取所有rect，再集中写入状态，避免读写交错。
- 观察器、ResizeObserver与MutationObserver共享注册表，不重复扫描整页。

## 五、第三阶段：首页内容与排版重构

### 1. 首页信息顺序

建议固定为：

1. 身份与当前重点。
2. 最近文章。
3. 当前项目；没有项目时隐藏主体，只保留一行入口。
4. 动态与相册；任一为空时自动让另一侧占满。
5. 简短关于与常用工具。
6. 常去的网站与留言入口。

空模块不再生成176至346px的大卡片。默认规则：0条隐藏内容容器，1条使用单项编辑布局，2条以上才使用网格或横向列表。

### 2. 首屏重构

- 只保留一张主要介绍表面；右侧“此刻状态”改成主卡内部的紧凑信息条或无卡片侧栏。
- 主标题建议直接表达身份和正在做的事情，例如“sau_baka，正在做 Cloudtrace”。
- 副标题改为事实描述：“记录 Flask 开发、界面设计和偶尔拍下的照片。”
- 删除胶带、闪光、轨道、`ONLINE`和虚线主题标签的同时堆叠，只保留头像或一张真实图片，以及一个小窗品牌标记。
- 首屏最多保留两个主要操作：“最近文章”“关于我”；相册改为普通文字链接。

### 3. 文案名称建议

| 当前名称 | 建议名称 |
| --- | --- |
| 窗边记录 | 个人记录 |
| 最近写下的东西 | 最近文章 |
| 正在发生的小项目 | 项目 |
| 最近的生活碎片 | 动态 |
| 装进胶片里的光 | 相册 |
| 关于这个小小星球 | 关于 sau_baka |
| FAVORITE TOOLS | 常用工具 |
| 相邻的小小星球 | 常去的网站 |
| 如果你也刚好路过 | 留言 |
| 作品桌还空着 | 暂无公开项目，或直接隐藏 |
| 今天还很安静 | 暂时没有动态，或直接隐藏 |
| 胶片盒还空着 | 相册尚未发布，或直接隐藏 |

后台仍允许覆盖这些标题；只修改系统默认值和当前用户明确选择应用的内容，不直接覆盖已有自定义文案。

### 4. 打破重复的卡片模板

- 最近文章采用编辑式横排：图片或编号占较窄区域，标题和摘要直接落在页面背景上，整行可点击。
- 项目使用一张有真实截图的宽卡；没有内容时不渲染装饰占位。
- 动态改成细时间线或两三行文本，不套大卡片。
- 相册以图片比例和留白为主，不在每张图片外再套厚白卡。
- 关于区由“一段简介 + 一列事实”组成，取消6张等权卡片。
- 友链使用简洁列表；留言作为页尾附近的单一操作，不再使用“星球连接”隐喻。
- 清除未渲染的`stats`配置，或在后台迁移中明确标记为已废弃，避免出现可配置但前台无效果的项目。

## 六、涉及文件

- `app/static/scripts/app.js`：目标注册器、滚动状态机、BFCache恢复、页面转场协调和动态节点处理。
- `app/static/styles/app.css`：边框后备、三档动效、悬停/按压、首页布局与响应式样式。
- `app/templates/public/home.html`：显式motion标记、首页区块结构、装饰清理和空状态策略。
- `app/services/content.py`：默认文案、模块元数据和废弃`stats`配置。
- 首页管理相关模板与路由：增加空内容展示策略和“是否应用新默认文案”的明确控制。
- `tests/test_frontend_contracts.py`及首页路由测试：覆盖目标协议、动态节点、BFCache、滚动阈值和文案结构。
- `bakagit`中的对应文件必须同步。

## 七、验收标准

### 动画

- 所有声明为surface/control的可见组件都有静态边界；0个透明边框但无SVG的组件。
- 首页按钮线条覆盖率100%，布局壳线条目标数为0。
- 初次加载时，页面转场与首屏卡片动画不重叠。
- 向下和向上滚动时，入场与出场都在组件仍有12%至30%可见时发生。
- 快速往返采样的进度连续，不回到0或1，不排队播放。
- BFCache返回、动态插入、折叠展开和隐藏后显示均能得到正确轮廓。
- 减少动态效果下内容立即可读，边框仍在，不出现透明卡片。

### 视觉与内容

- 桌面首屏不再由两张等权大卡占满；移动端在首屏或一次短滚动内能看到最近文章入口。
- 首页不超过两种主要卡片结构；空数据不会生成大面积占位卡。
- “小小/星球/最近/此刻”等重复词显著减少，英文装饰标签只保留有实际信息价值的内容。
- 关于区域不超过两个视觉容器；动态、相册和友链拥有不同的信息结构。
- 文章`11/111`只作为用户现有内容报告，不自动修改；发布真实内容后首页应自然替换。

### 技术回归

- JavaScript语法、Ruff、compileall、tinycss2、前端契约测试和完整pytest通过。
- 应用内浏览器检查桌面1280×900、平板768×1024、手机390×844；若工具无法设置精确视口，必须记录实际尺寸，不能冒充。
- 每个视口检查首帧、中间帧、完成帧、向下退出、向上重新进入、快速反向、控制台和横向溢出。
- 根目录与`bakagit`逐文件一致，Windows文件和正式SQLite用户内容不被静默删除。

## 八、推荐执行顺序

先完整完成第一阶段并单独验收滚动和覆盖率，再进行第二、三阶段。不要同时重写首页结构和观察器，否则难以区分是动画状态错误还是DOM结构变化。第一阶段稳定后，第二与第三阶段可以在同一次实现中完成，但必须分别验收“动效正确”和“内容去模板化”。

## 九、第三阶段实施结果

- 首屏由双卡并列改为单一介绍表面，当前重点、头像和相册文字入口收在同一结构中；主要按钮固定为两个。桌面高度压缩到约470px，首屏底部可看到下一段标题。
- 最近文章改为编辑式横排。封面存在时使用图文布局，无封面时采用收窄文字列；极短标题和摘要会自动降低字号与留白，不删除或修改原文章。
- 项目只展示一个主项目和后续文字索引。无项目时只保留64px左右的入口行，不再渲染大占位卡。
- 动态使用文字时间线，相册使用疏密图片网格；两者同时为空时整个组合区域不渲染，只有一方有内容时自动占满宽度。
- 关于区域压缩为简介与事实两个容器，技能改为普通文字列表。友链改为两列简洁列表，留言只保留页尾一个入口。
- 前台对旧系统默认标题和值做只读显示映射，不回写数据库；用户自定义标题、首页文案和文章内容保持原值。后台模块说明和字段名称同步为新结构，移除了已经不生效的项目布局选项。
- 新版首页禁用旧`content-visibility`预估高度，避免短页面滚动时发生高度跳变。首页静态卡片总数由原来的15张降到当前数据状态下的3张，空动态和空相册不产生占位。
