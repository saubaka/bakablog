# 项目8移植第六阶段：全量视觉、功能与性能验收

日期：2026-10-10。应用版本：Cloudtrace 1.42.0。

## 范围

只改当前项目1及其内部bakagit；源项目8只读，多用户版不改。首选端口5010、正式数据库（SHA-256 `5b38ba75…1016`，初始化未完成、无管理员）验收前后一致。这是规划中的最后一个阶段，六个阶段至此全部实施。

## 验收方法

项目要求的verify-web-visuals Skill在当前环境不存在，改用等价的组合：Playwright可见Chromium、`scripts/visual_probe.js`完整探针、专门编写的整站与运行时审计脚本，以及人工查看截图。应用内浏览器窗格隐藏时会暂停动画，所以交互验收都在Playwright中完成。验收用两个临时实例（带数据的5019和空站点向导的5029），随机密码不落盘到仓库。

## 发现并修复的问题

1. **长标题撑破页面（真实缺陷）**：文章页的“上一篇/下一篇”、相关文章卡片以及手机端归档列表，遇到没有空格的超长标题或网址时，网格子项不会收缩，页面出现横向滚动（手机上宽度达643px）。已在`app.css`加入收缩与换行保护（`min-width:0`、`overflow-wrap:anywhere`、归档列用`minmax(0,1fr)`），并新增契约测试。
2. **动态详情页没有`<h1>`（真实缺陷）**：`/moments/<id>/`在三端都缺少页面主标题，已补上视觉隐藏的`<h1>`。
3. **后台页面切换后观察者泄漏（真实缺陷）**：每个主题下拉各自创建一个`MutationObserver`，增强导航替换页面区域后不会断开，持续引用已移除的`select`（一轮后台导航后残留64个）。`ui-global.js`现在登记这些观察者，节点被移除后立即断开；复测残留为0。
4. **审计脚本规则**：期望404的页面（不存在的文章、404演示页）浏览器会打印一条“Failed to load resource … 404”控制台错误，审计规则已把这类预期错误排除。
5. **探针对页面高度的假设**：首页“关于”两张卡在手机上被测试数据撑长后，探针用的`scrollIntoViewIfNeeded`没有把第二张卡滚进视口（它距离视口底边仅3px，按设计保持未触发），而首页模块使用`content-visibility:auto`，首次滚动后高度才确定。探针改为滚动、等待布局稳定、再居中一次。这是探针问题，不是应用问题。

## 验收结果

- **整站页面审计**：443次页面加载（前台与后台路由，覆盖桌面1280、平板768、手机390，另有1440/1180/1024/901/900/360/320宽度、200%缩放和两种减少动态场景），检查状态码、水平溢出、元素溢出、原生select、损坏图片、未完成的动画、`will-change`残留、`<h1>`和控制台。最终结果：失败0。
- **运行时审计**：前台50次、后台40次增强导航后，监听器总数（37→37、27→27）、定时器、被观察的已移除节点（0）、动效与页面模块登记数均无增长，DOM增长在容许范围内，堆增长407KB/494KB（阈值6000KB），无页面错误。通知状态机检查通过：零时长、常驻错误、页面隐藏时冻结并恢复、减少动态、`textContent`防注入（脚本和图片未执行）、带操作通知、处理中被关闭、弹窗内点击与堆叠。
- **性能采样（仅本机一次采样，不代表目标环境）**：增强导航27次，网络中位数12ms，页面区域替换中位数160ms，P95为174ms；1767帧中位16.7ms、P95 16.8ms、最大33.3ms，超过34ms的帧0个，长任务0个；整页刷新18次中位32ms、P95 45ms。
- **完整`visual_probe.js`**：exit 0，9组动效样本、39个三端前台状态、120个三端后台状态，另含首帧、减少动态、轮廓生命周期、后台预览、动态注册、手机胶囊对齐、首页回入、编辑器菜单检查，自动问题0。
- **pytest**：220 passed，另有23条既有SQLite日期警告；Ruff和全部脚本语法检查通过。
- **人工截图抽查**：自动审计之外，人工查看了代表性截图——手机上的长标题长网址文章、手机首页、平板留言簿、桌面相册详情、桌面后台文章编辑、平板后台“弹窗与通知”（含通知动效编辑器）；修复后另拍了长标题文章的手机截图复核。这些页面没有发现裁切、重复描边或残留动画。其余页面由自动审计的溢出、裁切、动画残留检查覆盖，没有逐张人工查看。
- 证据目录为`session-data/qa/v1.42.0-project8-phase6`：`audit-pages.json`、`audit-runtime.json`、`probe/report.json`和截图。

## 未验证与已知范围

- 性能数字来自开发机上的一次本地采样，没有在目标Debian或macOS LaunchAgent部署环境、慢速网络或低端设备上测过。
- 相册详情的瀑布流使用CSS多列：照片很少（例如4张）时右侧会留出空列，这是既有行为，本阶段没有改动。
- 文章和独立页面编辑器仍走原生跳转，规划里的独立浮动子菜单没有实现（第四阶段已说明）。
- 并发保存保护只覆盖“弹窗与通知”表单，其他设置页仍是最后写入为准。
- 没有提交、推送或发布。临时实例、测试数据和密码在验收结束后清理。
