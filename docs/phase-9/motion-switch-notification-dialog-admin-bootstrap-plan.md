# Cloudtrace 右下角浮层、后台视觉与管理员初始化重构规划

规划版本：1.0  
预计应用版本：1.36.0  
状态：已实施；2026-09-17完成代码与数据复核，剩余三项收尾见第十七节  
适用基线：Cloudtrace 1.35.0 / SQLite迁移`b7d2f0a64e19`

## 一、目标与边界

本次重构同时解决四类问题：

1. 删除前台与后台所有页面右下角的“动效：跟随系统 / 动效：精简”切换控件。
2. 重构右下角通知栏的配色、结构、线条和进入/退出动画，使其与主页浅色“小窗”风格一致。
3. 重构确认、提示、输入、媒体预览等弹窗的配色、结构、线条和动画，统一当前多代样式覆盖。
4. 建立安全的“无超级管理员初始化”流程；在流程经过验证后清空现有管理员凭据和会话，使访问`/bakaadmin`时可以创建新的唯一超级管理员。
5. 管理后台继续保持高信息密度与左侧导航结构，但全面复用主页的颜色、圆角、线条和物理动画协议。

本次不恢复普通用户、公开注册、公开登录、个人中心或多管理员体系。所谓“创建管理员”始终只指初始化唯一的超级管理员。

## 二、现状结论

- 页尾`app/templates/components/site_footer.html`固定输出`data-motion-toggle`按钮。
- `app/static/scripts/app.js`使用`cloud-diary-motion`本地存储键切换`html[data-motion]`，并注册右下角按钮事件。
- 当前通知使用`.toast-region`与`.toast`，结构只有状态圆点、正文和关闭按钮；主要动画是整体向上移动12px并淡入，没有描边阶段、表面阶段和可中断退出。
- 当前系统弹窗由原生`dialog`承载，这一点应保留；但`.modal`和`.app-system-dialog`存在多组历史覆盖、渐变和不同入场动画，视觉层次不统一。
- 后台已经读取全局颜色变量，但`.admin-body`、侧栏、面板、导航、顶部栏和部分卡片仍保留独立硬编码色值与阴影。
- 正式数据库目前存在1个活动超级管理员。直接删除该行会触及文章作者、媒体创建者、审计等外键，因此不能用简单`DELETE FROM users`实现安全清空。

## 三、统一视觉令牌

### 3.1 全局基础令牌

以下令牌同时服务主页、后台、通知和弹窗：

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| 页面底色 | `#F7F9FC` | 前后台主背景 |
| 浅表面 | `rgba(255,255,255,.92)` | 普通卡片、弹窗主体 |
| 云朵蓝 | `#E5EFFB` | 当前项、信息通知、轻强调 |
| 花瓣粉 | `#F7E5ED` | 少量提醒、危险操作前的柔和提示 |
| 银雾灰 | `#E9EDF2` | 输入框、静态轨道、次级区域 |
| 主文字 | `#354052` | 标题、正文、图标 |
| 晴蓝 | `#526FA6` | 链接、焦点、主操作 |
| 普通线条 | `#C9DDEA` | 卡片、通知、弹窗轮廓 |

语义状态使用低饱和独立令牌，并保证文字对比度：

- 成功：表面`#F2FAF5`、线条`#BFDCC9`、文字`#426B51`。
- 警告：表面`#FFF9ED`、线条`#E7D6A7`、文字`#775F2B`。
- 错误：表面`#FFF3F2`、线条`#E5C1BE`、文字`#80504D`。
- 信息：表面`#F3F8FD`、线条`#C9DDEA`、文字`#4E6B84`。

### 3.2 材质约束

- 主体卡片不再使用交替蓝粉渐变；统一为浅白表面、淡蓝细线和轻微蓝灰阴影。
- 玻璃模糊只允许用于面积较小的通知、弹窗遮罩和浮动工具栏；后台大面积容器禁止持续模糊。
- 通知圆角20px，普通弹窗22px，大型媒体/裁剪弹窗26px；关闭按钮保持圆形。
- 线条始终为单条连续路径，不叠加CSS边框动画、双SVG描边、扫描光或循环发光。

## 四、删除右下角动效切换

### 4.1 模板和脚本

- 从`site_footer.html`删除`data-motion-toggle`按钮，页尾只保留版权和必要链接。
- 删除`app.js`中的按钮文本同步、点击监听和写入`cloud-diary-motion`的逻辑。
- 首次加载时主动移除旧版本留下的`cloud-diary-motion`本地存储键，避免升级后旧偏好继续覆盖新逻辑；清理仅执行一次并可安全失败。
- 删除仅服务该按钮的CSS，包括右下角定位、按下态和移动端避让规则。

### 4.2 可访问性保留

- 删除的是页面控件，不删除`prefers-reduced-motion`支持。
- 系统开启“减少动态效果”时，页面仍自动使用静态轮廓、即时表面和短淡入反馈。
- 后台“主题 → 动画”仍负责站点级动画样式与时长；不能在每台访客设备右下角覆盖站点设置。

### 4.3 验收

- 任意前后台页面DOM中`[data-motion-toggle]`数量为0。
- 桌面、平板、手机页尾不留下空白按钮位或不均匀对齐。
- 浏览器内旧`cloud-diary-motion`值不会继续改变页面状态。
- 系统减少动态效果仍能覆盖卡片、通知、弹窗和页面切换。

## 五、右下角通知栏重构

### 5.1 组件结构

统一通知结构为：

1. 小窗状态标记：两片略不对称圆角窗格，不使用普通彩色圆点。
2. 文本区：可选短标题、正文；长内容最多三行，超出时提供明确展开或跳转操作，不直接裁切重要信息。
3. 操作区：可选操作按钮和圆形关闭按钮。
4. 生命周期线：沿通知卡片轮廓运行，同时表达入场完成与自动关闭剩余时间；暂停悬停、键盘焦点和触摸阅读时的倒计时。

通知最多同时显示3条；更多通知进入内存队列。新通知插入顶部，旧通知通过`transform`平滑下移，不触发连续布局抖动。

### 5.2 单线条入场协议

总时长默认360ms，使用同一个可中断Web Animations时间轴：

- `0–42%`：单条轮廓从上边缘偏左的小窗起点沿真实圆角绘制。
- `12–62%`：浅色表面从背景中以`opacity + scale(.985→1) + blur(3px→0)`浮现。
- `44–82%`：小窗标记、标题和正文以2px位移及轻微模糊出现。
- `62–92%`：操作和关闭按钮出现；按钮自身不抢先播放独立卡片动画。
- `92–100%`：阴影稳定并清除`will-change`、动画对象和临时测量值。

退出默认220ms，按相反视觉顺序缩短执行：先隐藏文字和操作，再减弱表面，最后让单线条收回起点。手动关闭、自动关闭、路由切换和重复消息合并都调用同一个可中断状态机，不允许动画排队。

### 5.3 状态与交互

- `info / success / warning / error`只改变语义令牌、小窗标记和可读图标，不改变整体布局。
- 相同内容在短时间内重复出现时合并为一条并显示次数，避免通知风暴。
- 错误通知不自动关闭；成功和信息默认5秒，警告默认8秒，均可由后台设置限制在3至15秒。
- `aria-live="polite"`用于普通通知；阻断性错误使用`assertive`但不得重复朗读。
- 关闭后焦点不被强制移动；带操作按钮的通知必须支持Tab和Enter。

### 5.4 响应式

- 桌面端：右22px、底22px，宽度320至390px。
- 平板端：右16px、底16px，避开后台抽屉和粘性保存条。
- 手机端：左右各12px，宽度自动；底部位置使用`max(88px, env(safe-area-inset-bottom) + 76px)`避开胶囊菜单。
- 横屏矮视口改为顶部右侧显示，避免遮挡表单提交按钮。

## 六、弹窗重构

### 6.1 统一组件族

保留原生`dialog`语义，统一以下类型：

- 确认弹窗：标题、正文、取消、确认。
- 提示弹窗：标题、正文、单一确认。
- 输入弹窗：固定标签空间、输入框、错误区域和操作按钮。
- 表单弹窗：友链申请等中型表单。
- 媒体弹窗：图片预览、媒体选择、裁剪和编辑。

所有浏览器`alert / confirm / prompt`继续由项目组件接管；不得重新使用浏览器默认弹窗。删除历史样式中“左侧大色块”“云朵凸起”“虚线纸张”等互相冲突的结构，保留一种核心骨架和紧凑/普通/大型三种密度。

### 6.2 弹窗视觉结构

- 顶部：小窗标记、标题、圆形关闭按钮。
- 中部：正文或表单，错误区域预留空间。
- 底部：操作按钮统一靠右，手机端可上下排列但主操作保持最后。
- 危险操作只使用淡红轮廓和明确动词，不使用大面积红底。
- 遮罩使用低透明石墨蓝灰；默认模糊不超过4px，低性能模式完全关闭模糊。

### 6.3 单线条动画协议

默认打开总时长420ms：

- `0–36%`：遮罩淡入至目标透明度，同时单轮廓线从顶部小窗标记处开始绕弹窗闭合。
- `10–58%`：弹窗表面以`opacity + scale(.975→1) + blur(4px→0)`浮现，不进行大距离上下滑动。
- `46–82%`：标题、正文和表单统一出现。
- `66–94%`：底部操作按钮和关闭按钮出现。
- `94–100%`：焦点进入首个合理控件，清理临时合成层。

关闭使用260ms可逆时间轴；按Escape、点击关闭、确认、取消和路由离场都先完成退出状态，再调用`dialog.close()`。连续点击时反转当前时间轴，不创建第二套动画。

图片灯箱从缩略图位置展开仍可保留，但最终表面、圆角、遮罩和关闭动画使用同一令牌；无法获得缩略图几何时退回标准弹窗动画。

### 6.4 焦点和键盘

- 打开后焦点进入标题后的首个可操作元素；关闭后恢复到触发按钮。
- 原生Escape关闭必须进入统一退出动画，不能瞬间消失。
- 遮罩点击关闭只用于非破坏性弹窗；危险确认和正在上传的弹窗禁止误触关闭。
- 提供`aria-labelledby`、`aria-describedby`；动态错误使用独立`aria-live`区域。
- 减少动态效果时仅保留120ms透明度变化，不缩放、不模糊、不移动。

### 6.5 后台设置与预览

现有“主题 → 弹窗”页面重构为“弹窗与通知”，不增加新的母菜单：

- 弹窗：强调色、圆角、宽度、遮罩透明度、遮罩模糊、阴影密度、动画时长。
- 通知：宽度、圆角、停留时间、堆叠间距和四种语义色预览。
- 预览区必须调用生产组件，不使用单独伪造的演示CSS。
- 提供确认、提示、输入、成功通知、警告通知和错误通知六种实际预览。

## 七、后台与主页视觉同步

### 7.1 同步原则

后台不复制主页的内容排版，而是共享同一视觉语言：

- `body`背景、卡片表面、输入框、按钮、当前菜单项、焦点环和文字层级全部使用全局令牌。
- 左侧栏采用主页顶部胶囊相同的浅白透明度、淡蓝线条和阴影强度；不使用额外彩色渐变。
- 当前菜单项使用云朵蓝填充与晴蓝文字；展开项只用线条、背景色和高度变化区分。
- 后台面板使用18至22px圆角；表格行和高密度条目使用10至14px圆角，避免所有内容都成为大胶囊。
- 主按钮、次按钮、图标按钮、选择卡片、通知和弹窗共享主页组件状态。

### 7.2 线条与页面动画

- 后台`.admin-panel`、主要编辑器容器和空状态接入主页现有单路径物理阻尼引擎。
- 密集列表行不逐行绘制完整大轮廓；列表容器绘制主线，行只做80至140ms背景/位移反馈，避免几十条动画同时运行。
- 左侧菜单展开只动画`grid-template-rows/opacity/transform`中的轻量组合，并确保同一时间只展开一个母菜单。
- 后台跨页面过渡继续支持当前配置，但内容卡片入场必须等待页面遮罩进入后再启动，避免两套模糊同时运行。
- 动画完成后清除所有`will-change`；同屏最多3个主表面同时绘制线条。

### 7.3 CSS治理

- 在`app.css`末端建立单一`Cloudtrace 1.36`令牌与组件层，随后逐步删除被覆盖的旧toast、modal、admin硬编码规则，避免继续靠更高优先级叠加。
- 禁止在组件中直接写具体蓝色或阴影，全部引用CSS变量。
- 使用`data-surface-role="page|panel|list|floating"`和`data-motion-role`表达密度，不根据页面路径复制选择器。
- 前台和后台Jinja均调用同一通知、弹窗与线条组件宏。

## 八、无管理员初始化与数据清空

### 8.1 安全原则

实现顺序必须是“先建立并验证初始化流程，再清空正式管理员凭据”。任何情况下都不得先删除当前管理员导致永久锁死后台。

系统区分三种状态：

1. `ready`：存在且仅存在一个活动超级管理员，`/bakaadmin`显示登录。
2. `setup_required`：不存在活动超级管理员，`/bakaadmin`显示唯一管理员初始化表单。
3. `setup_locked`：初始化正在进行或短期失败次数过多，拒绝并发创建。

### 8.2 初始化入口

- 入口仍为`/bakaadmin`，不新增公开`/register`路径。
- 初始化表单包含：用户名、显示名称、密码、确认密码、本地图片人机验证；生产环境额外需要一次性初始化码。
- 开发环境只允许来自`127.0.0.1`或`::1`的无管理员初始化；通过局域网/IP访问时仍要求一次性初始化码。
- 生产环境必须通过本地命令`flask admin-bootstrap-code`或`bakablog`管理菜单生成10分钟有效的一次性码。数据库和运行文件只保存摘要，不记录明文。
- 创建过程使用SQLite写锁和事务再次检查活动超级管理员数量，防止两个请求同时创建。
- 创建成功后立即废止初始化码、轮换会话、登录新超级管理员并跳转仪表盘；第二次访问自动恢复普通登录页。

### 8.3 管理员数据清空策略

新增受保护命令`flask reset-superadmin`，只允许交互式确认或显式高强度确认参数：

1. 强制生成完整站点备份并验证ZIP和SQLite哈希；备份失败则停止。
2. 撤销并删除全部后台会话，清空登录失败窗口和临时人机验证。
3. 将审计记录中的操作者保留为历史匿名引用，不删除站点内容和审核记录。
4. 选择一个现有管理员行作为“待初始化槽位”：移除角色、写入不可登录的随机密码摘要、替换用户名与显示名、设置`is_active=false`。这样文章作者、媒体创建者等非空外键继续有效。
5. 如果存在额外管理员行，先把内容所有权安全归并到该槽位，再删除额外行。
6. 写入`setup_required`状态并生成一次性初始化码；命令输出备份路径、初始化地址和码的过期时间，不把明文写入日志。

新管理员创建时复用该槽位ID，恢复用户名、显示名、密码、`superadmin`角色与全部当前权限。由此既真正清空旧凭据和会话，又不破坏文章、媒体、版本和审计外键。

### 8.4 登录和初始化限流

- 登录继续使用按访问来源指纹计算的失败次数，避免按用户名锁死账号。
- 初始化码、人机验证和表单密码分别计数；任一项失败不泄露系统当前是否存在特定用户名。
- 初始化页面连续失败5次后锁定15分钟；刷新验证码不重置失败次数。
- 初始化成功后删除全部未使用初始化码，记录一条不含密码、验证码和初始化码的安全审计事件。

### 8.5 恢复路径

- 如果初始化页面本身异常，可通过`flask create-superadmin`在本地终端恢复；该命令与网页初始化调用同一个服务层。
- 如果迁移或清空中断，`reset-superadmin`必须能根据状态文件判断是否回退备份，不能重复清空。
- Debian/macOS的`bakablog`管理菜单增加“重置唯一管理员”和“生成初始化码”，Windows继续使用Flask CLI，不删除现有Windows文件。

## 九、数据与代码结构

### 9.1 服务层

- 新增`app/services/admin_bootstrap.py`：状态检查、一次性码、原子初始化、槽位复用、重置和恢复。
- `app/blueprints/admin/routes.py`只负责选择登录或初始化视图、表单校验和响应。
- `app/cli.py`的`create-superadmin`、`admin-bootstrap-code`和`reset-superadmin`共同调用服务层，禁止复制账号创建逻辑。
- `app/services/auth.py`负责会话撤销和建立，不处理初始化状态。

### 9.2 表单与模板

- 新增`SuperadminSetupForm`，密码至少14位并要求确认。
- `admin/login.html`拆成共享品牌壳，内部按状态渲染登录表单或初始化表单。
- 通知和弹窗结构抽到`app/templates/components/overlays.html`或等价宏文件，避免每个页面重复HTML。

### 9.3 数据库

预计新增迁移：

- `admin_bootstrap_tokens`：只保存令牌摘要、创建时间、过期时间、使用时间和失败次数。

## 十三、主要风险与控制

1. **管理员锁死**：初始化流程和CLI恢复未在隔离库通过前，禁止清空正式管理员。
2. **内容外键断裂**：不直接删除唯一管理员主键，使用不可登录槽位并在创建时复用。
3. **公开抢注后台**：生产环境无管理员时必须使用短时一次性初始化码；不能只依赖页面处于隐藏路径。

5. **旧CSS继续覆盖**：实施时删除旧规则，不只在文件末尾追加更高优先级覆盖。
6. **移动端遮挡**：通知、弹窗按钮和底部胶囊必须纳入安全区与390/320px实图验收。
7. **可访问性退化**：移除手动动效按钮后仍必须完整尊重系统减少动态设置；弹窗焦点、Escape和读屏语义不可弱化。

### 17.2 仍然存在的问题

复核过程中确认了三项真实缺口，它们不是“没做”，而是“做得还不够稳”：

1. 启动端口没有预检。本机`5000`当前由macOS的`ControlCenter`（AirPlay接收器）占用，Cloudtrace在该端口没有监听，`start-macos.sh`也不会在端口被占用时自动换端口，按默认方式启动会直接失败或看到别的服务页面。
2. 远程初始化缺少引导。`setup_code_required()`在非回环访问或生产环境下返回真值，此时创建页必须填写命令行签发的一次性口令，但页面没有说明口令怎么来，失败时也不区分“口令过期”和“图片字符不匹配”。
3. 覆盖层用到了较新的CSS能力。`color-mix()`6处、`@property --overlay-angle`和`mask-composite`在较老的Safari与Chromium上会静默退化，通知和弹窗仍能显示（旧规则提供底色），但线条动画会退成纯淡入。

### 17.3 收尾阶段规划

阶段一，兼容与启动（改动最小、收益最直接）：

- 为通知与弹窗补`@supports not (background: color-mix(in srgb, #fff, #000))`分支，给出等价的固定回退色，保证老内核拿到同一套浅色观感。
- 启动脚本在绑定前探测目标端口，被占用时按既定顺序寻找空闲端口，把实际端口打印到终端并写入本地状态文件；显式`--port`时仍以用户指定值优先，只在被占用时提示并回退。
- 保留`prefers-reduced-motion`降级不变，回退分支同样在减少动态时关闭线条并把过渡压缩到1ms。

阶段二，初始化体验：

- 创建页在需要口令时显示一句获取方式说明，并把“口令无效或已过期”与“图片字符不匹配”分成两种提示，避免用户反复重试同一个原因。
- 初始化成功后回写状态并给出一次明确的成功反馈；口令一次性作废，有效期保持30分钟。
- 命令行路径（`flask issue-admin-setup-code`、`flask reset-superadmin --yes`）与页面路径保持同样的文案和错误分类。

阶段三，验收与发布：

- 按视觉验收矩阵在1280×900、768×1024、390×844以及320px初始化页复验通知、弹窗、后台菜单和首页；检查溢出、裁切、控制台错误、动效漏接与减少动态。
- 逐帧抽查通知360ms与弹窗420ms的线条轨迹，确认入场可中断、退场可打断、后台预览与前台一致。
- 只有在前两阶段改动了代码时才提升版本号并同步`updates/stable.json`、根目录与`bakagit`，同时把结论写回`session-data`。
