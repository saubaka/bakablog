# 更淡的浅蓝配色（1.43.0）

日期：2026-10-10。应用版本：Cloudtrace 1.43.0。只改项目1及内部bakagit；源项目8只读，多用户版不改；5010、正式数据库不变。

## 要求与取舍

要求：检索整个项目与线条和配色有关的页面、内容和样式，全部改为更淡的浅蓝色。

处理原则：线条、描边、轮廓、装饰填充和装饰图标整体向白色靠拢；**文字颜色和键盘焦点环保持原来的蓝色**，否则链接、眉题和焦点位置会读不清。线条变淡后，输入框等控件的边框对比度比之前低，这是该要求的直接结果。

## 做了什么

- **样式表**：用基于tinycss2的位置替换脚本，只改边框、描边、轮廓、背景填充、环形阴影、控件强调色和主题变量中的蓝色（色相185°–250°、明度0.45–0.935，向白色移动42%），不改文字色、普通投影和浅于0.935的页面底色。`app.css`中边框、描边、轮廓、背景里明度低于0.80的蓝色从113处降到26处，通知样式表中的从2处降到0。
- **主题令牌**（`small-window-theme.css`）：`--line-blue` #dceaf7→#ebf3fa，`--line-blue-strong` #bed8ef→#d9e8f6，`--blue-200` #d3e5f6→#e5f0fa，`--cloud-blue` #e5effb→#edf4fc，新增`--accent-soft` #99abcd用于复选框强调色、范围滑块手柄、后台菜单标记、加载圈、时间线圆点、Logo窗口符号、卡片箭头和装饰图标。`--sunny-blue` #526fa6仍用于文字和焦点环。
- **后台默认值**：动效线条色 #91BED8→#BFD9E8，通知强调色同上，弹窗轮廓色 #526FA6→#99ABCD，页面切换起始色 #E5EFFB→#EDF4FC。模板和脚本里的回退值同步。
- **已保存的旧默认值**：正式数据库里保存着旧默认值（例如弹窗轮廓色 #526FA6）。读取时把这几个“旧默认值”视为未自定义，自动采用新默认值；不修改数据库，后台表单也显示新值。用户自己选过的其他颜色不受影响。副作用：有人恰好手选了与旧默认相同的颜色，也会被换成新默认值。
- **新增测试**：色板明度契约、旧默认值解析，并更新了固定旧色值的断言（pytest共222个通过）。

## 验证

- 浏览器逐页实测所有前后台路由里元素的计算样式：边框、轮廓、SVG描边、环形阴影、背景、强调色。修复前后对比，线条与填充里的深蓝已清除；剩余深蓝的描边几乎都是跟随文字色的图标（文字链接的箭头、手机底部当前项等），按原则保留。
- 完整`visual_probe.js` exit 0（9组动效、39个公开页面状态、120个后台状态）；全站审计443次加载失败0。
- 截图（桌面首页、后台仪表盘、弹窗与通知页、通知胶囊、确认弹窗、手机首页等）在`session-data/qa/v1.43.0-light-blue-scheme`，人工看过这些截图，线条与装饰色明显变淡，文字清晰。其余页面靠自动检查，没有逐张人工查看。
- verify-web-visuals Skill在当前环境不存在，用Playwright与上述脚本代替。

## 没有改的

- 站点图标`cloud-diary-app.svg`和图片验证码里的干扰线：前者是品牌文件，变淡后在浏览器标签里难以辨认；后者的干扰线是防自动识别的一部分。
- 成功、提醒、错误通知的绿、琥珀、红色，以及花瓣粉，它们不是蓝色。
- 文字蓝色（链接、眉题、当前项文字）和焦点环。如需把文字蓝也调淡，会降低可读性，需要单独决定。
