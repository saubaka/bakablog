# UI完善第一阶段视觉审计

审计日期：2026-07-16  
范围：前台、后台公共CSS、阅读页、手机导航和组件展示页。

## 已确认并在第一阶段处理

- 阅读页：顶部进度计算不稳定，目录卡缺少实际进度条和百分比。
- 手机菜单：遮罩与抽屉缺少统一状态，抽屉没有动态视口高度和内部滚动兜底。
- 按钮：原按压只有`scale(.97)`，阴影、表面和释放层次不足。
- 卡片：多数页面共用相同白色卡片、相同边框和相同阴影。
- 表单：输入框虽然有圆角，但背景、Hover、错误提示和聚焦层次单薄。
- 裸控件：首页模块、导航配置、媒体说明和行内回复存在未完全继承`.field`外观的输入框。
- 后台：表格、面板、分页和上传区的圆角与色彩层次不足。
- 色彩：浅蓝使用集中，粉、薄荷、奶油和紫色缺少组件级语义分工。

## 本阶段统一规则

- 控件圆角统一为14～18px，普通面板18～24px，大浮层28～34px。
- 主按钮使用蓝色渐变；粉色用于柔和强调，薄荷用于完成，奶油用于提醒。
- 交互控件必须具备默认、Hover、按下、焦点、禁用状态。
- 卡片使用顶部高光、低对比边界和两段柔和阴影；可点击卡片才提供浮起效果。
- 所有表单错误同时显示背景、边框和文字提示。
- 原生功能与可访问语义保持不变，视觉样式不能替代真实标签与焦点。

## 延后到后续阶段

- 首页模块重排和新增内容属于第二阶段。
- 完整进入动画、指针倾斜与复杂物理反馈属于第二阶段。
- 自建文章与图片布局编辑器属于第三阶段。
- 各业务页面完全差异化属于第四阶段。

## 完成与验证

- 已发布为应用版本`1.2.0`，静态资源版本同步变化，旧CSS/JavaScript缓存会自动失效。
- 阅读进度改为基于文章绝对起止位置、动态视口和内容尺寸变化计算；顶部与目录内两条进度保持同步，并显示百分比和预计剩余时间。
- 手机菜单使用统一开关状态、焦点进入/返回、页面`inert`、滚动锁、动态视口高度和内部滚动；同时修复桌面菜单按钮被通用图标按钮样式意外显示的CSS优先级问题。
- 公共UI 2.0已覆盖视觉Token、按钮、输入框、卡片、标签、Toast、弹窗、分页、表格、上传区和主要后台面板。
- 自动化结果为87项pytest通过，Ruff检查和格式检查、JavaScript语法与`pip check`通过。
- Chromium真实浏览器已复验1440、768、390和320 CSS像素：菜单开关、阅读进度、圆角和组件色彩正常，无横向溢出、控制台警告或远程必需资源。
