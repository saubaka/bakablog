# 阶段四数据模型与权限说明

## 数据表

| 表 | 关键字段 | 用途 |
| --- | --- | --- |
| `users` | 用户名、显示名、密码哈希、启用状态、最近登录 | 本地管理员身份 |
| `roles` | 角色代码、名称、系统角色标记 | 权限集合 |
| `permissions` | 权限代码、名称、说明 | 服务端授权粒度 |
| `user_roles` | 用户、角色复合主键 | 用户与角色多对多关系 |
| `role_permissions` | 角色、权限复合主键 | 角色与权限多对多关系 |
| `media` | 本地路径、缩略图、尺寸、MIME、替代文字、创建者 | 本地媒体元数据 |
| `login_logs` | 用户名、结果、地址、User-Agent、时间 | 成功与失败登录追踪 |
| `audit_logs` | 操作者、动作、目标、请求标识、地址、时间 | 关键后台操作追溯 |
| `alembic_version` | 当前迁移版本 | 数据库结构版本 |

删除角色或用户关联时通过外键级联清理关联表；删除仍被媒体引用的创建者会被限制。登录和审计记录在用户被删除后保留，并把操作者外键设为空。

## 内置权限

- `dashboard.view`：查看后台仪表盘。
- `media.view`：浏览媒体库。
- `media.manage`：上传与删除媒体。
- `users.view`：查看用户和角色。
- `audit.view`：查看审计与登录日志。
- `system.maintain`：预留给本地维护操作。

初始化生成的 `administrator` 角色包含全部内置权限。页面隐藏只用于改善界面，真正的权限判断始终在服务端装饰器中执行。

## SQLite 策略

每个 SQLAlchemy SQLite 连接都设置：

```text
PRAGMA foreign_keys=ON
PRAGMA journal_mode=WAL
PRAGMA busy_timeout=5000
PRAGMA synchronous=NORMAL
```

列表、状态、创建时间、用户名、权限代码、角色代码、日志动作和目标均建立了针对性索引。媒体处理在数据库事务之外完成，数据库写入保持短小；提交失败时会清理已经生成的本地文件。

SQLite 仍按“单机、读多写少、单写入者”边界使用。第二个写入者会等待第一个短事务提交；自动化测试已验证等待后两条记录都能提交，不会静默丢失。

## 媒体安全边界

- 不使用用户文件名作为磁盘路径，文件名由随机 UUID 生成。
- 使用 Pillow 按真实内容识别格式，而不是信任扩展名或请求 MIME。
- 仅接受 JPEG、PNG 和 WebP。
- 默认单文件最大 8MB、最大 2400 万像素。
- 重新编码原图以清除不必要元数据，并生成最大 640×640 的 WebP 缩略图。
- 公开媒体路由只提供已经登记在数据库中的相对路径。
