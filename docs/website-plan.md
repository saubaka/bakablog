# 独特可爱风个人网站总体规划

阶段一详细需求与技术方案见[阶段一交付物索引](phase-1/README.md)，阶段二设计与原型见[阶段二交付物索引](phase-2/README.md)，阶段三可运行骨架与组件见[阶段三交付物索引](phase-3/README.md)，阶段四数据库与后台基础见[阶段四交付物索引](phase-4/README.md)，阶段五博客业务闭环见[阶段五交付物索引](phase-5/README.md)，阶段六个人内容与首页配置见[阶段六交付物索引](phase-6/README.md)。

## 1. 项目定位

建设一个“个人数字花园 + 博客 + 个人名片 + 作品集 + 轻社区”的个人网站。网站既能长期发布文章，也能展示个人介绍、经历、项目、动态、相册、收藏与友情链接。

核心目标：

- 使用浅蓝、浅粉、浅灰、白色构建柔和、耐看的浅色主题。
- 排版具有辨识度，同时保持内容层级和阅读体验清晰。
- 使用卡片、圆角、胶囊菜单、便签、云朵与贴纸等可爱元素。
- 动效具有柔和的弹性、惯性和物理反馈，操作响应及时。
- 前台所有内容和展示模块都能在后台管理。
- 兼容桌面、平板和手机，并支持触控、键盘和减少动态效果。
- 兼顾性能、可访问性、SEO、安全性和后续扩展能力。

### 1.1 固定技术与运行约束

本项目不再进行框架和数据库选型，后续设计与开发必须遵守以下基线：

- 使用 Python 和 Flask 构建整个项目。
- 使用 Flask 应用工厂、Blueprint 和服务层组织模块化单体应用。
- 使用 Jinja2 完成前台和后台的服务端页面渲染，原生 JavaScript 负责渐进增强。
- 使用 SQLite 作为唯一业务数据库，数据库文件存放在本地实例目录。
- 使用 SQLAlchemy 访问数据，使用 Alembic/Flask-Migrate 管理数据库迁移。
- 上传文件、图片缩略图、备份、日志、字体、图标、CSS 和 JavaScript 全部本地保存。
- 不使用 CDN、云对象存储、外部数据库、Redis、远程搜索服务或必须联网运行的第三方接口。
- Python 依赖安装在项目虚拟环境，锁定版本，并可通过本地 wheel 包目录离线恢复。
- 前端不以 Node.js 为运行前提；如确需构建工具，其产物和工具链也必须本地锁定，生产环境只运行已构建文件。

这里的“高性能”定位为高性能的单机个人网站：重点优化读取、缓存、查询、静态资源和图片，而不是追求不符合 SQLite 特性的无限写入并发或多机水平扩展。

## 2. 主题概念

暂定主题概念为“云朵手账”。整个网站像一本漂浮在浅色天空中的个人手账：

- 文章表现为便签或信纸卡片。
- 项目表现为可展开的小档案盒。
- 友链表现为漂浮的小星球或好友名片。
- 时间线表现为柔软的彩色丝带。
- 菜单表现为悬浮软糖胶囊。
- 图片可使用拍立得、胶带或贴纸边框。

装饰元素必须服务于内容，不应遮挡文字、降低对比度或造成视觉噪声。

## 3. 视觉设计系统

### 3.1 色彩

| 用途 | 建议颜色 |
| --- | --- |
| 页面背景 | `#F8FAFD` |
| 卡片背景 | `#FFFFFF` |
| 主浅蓝 | `#BFDDF7` |
| 强调蓝 | `#75AEE8` |
| 主浅粉 | `#F6CADB` |
| 强调粉 | `#E99BB8` |
| 辅助浅紫 | `#DDD4F7` |
| 辅助浅绿 | `#D5EDDF` |
| 主要文字 | `#3F4654` |
| 次要文字 | `#7C8494` |
| 边框 | `#E8ECF2` |

色彩规则：

- 白色和浅灰作为大面积背景，浅蓝作为主要交互色，浅粉作为点缀色。
- 避免大面积高饱和颜色。
- 正文、按钮和状态信息需保持足够对比度。
- 错误、成功、警告等状态必须同时使用文字或图标，不能仅依赖颜色。

### 3.2 圆角、阴影与间距

- 小圆角：8px。
- 表单与普通按钮：12～14px。
- 卡片：18～22px。
- 大型容器：24～30px。
- 胶囊按钮：999px。
- 阴影采用浅灰蓝多层柔和阴影，避免浓重黑色投影。
- 使用统一的4px或8px间距体系，避免页面出现无规律空隙。

### 3.3 字体与排版

- 中文正文采用清晰的现代无衬线系统字体栈。
- 英文标题可使用较圆润的几何字体。
- 代码区域使用等宽字体。
- 正文字号以16～18px为主，行高控制在1.7～1.9。
- 文章正文最大宽度控制在680～820px。
- 首页主标题约40～56px，页面标题约32～40px，卡片标题约18～24px。

## 4. 响应式布局

### 4.1 桌面端

- 左侧为悬浮个人资料胶囊或快捷导航。
- 中间为主要内容流。
- 右侧放置状态、目录、推荐内容等辅助组件。
- 首页采用轻度不对称卡片布局，通过不同尺寸和位置形成独特节奏。
- 导航可收起为圆形按钮，展开后成为软糖胶囊菜单。

### 4.2 平板端

- 收紧三栏布局，必要时隐藏右侧辅助栏。
- 保留主要导航和内容层级。
- 卡片由多列自动调整为两列或单列。

### 4.3 移动端

- 使用单列信息流。
- 顶部展示头像、昵称和状态，底部使用悬浮圆角导航。
- 侧栏组件移动到正文后方或放入抽屉。
- 所有主要触控区域不小于44×44px。
- 不能依赖鼠标悬停完成关键操作。
- 适配刘海屏、圆角屏和底部安全区域。

## 5. 前台页面与功能

### 5.1 首页

- 个人欢迎卡、头像、昵称、签名和当前状态。
- 社交平台入口和联系方式。
- 最新文章、精选文章和分类入口。
- 项目作品、相册、动态和友链预览。
- 技能标签、个人时间线、公告或随机语录。
- 后台可控制模块开关、排序、样式、展示数量与设备可见性。

### 5.2 博客列表

- 文章封面、标题、摘要、发布日期、阅读时间、分类和标签。
- 分类、标签、关键词、年份和精选状态筛选。
- 最新、热门等排序方式。
- 卡片与紧凑列表两种展示模式。
- 分页或渐进加载。

### 5.3 文章详情

- 标题、摘要、封面、作者、发布日期、修改时间、字数和阅读时间。
- Markdown或富文本正文、代码高亮、表格、引用和提示块。
- 自动目录、阅读进度、图片灯箱和代码复制。
- 分类、标签、版权信息、上一篇、下一篇和相关文章。
- 点赞、分享、评论以及可选的修改记录。

### 5.4 关于我

- 个人介绍、头像或插画。
- 兴趣爱好、技能标签和当前目标。
- 学习或工作经历时间线。
- 常用设备、工具、社交方式和简历下载。
- 可配置的个人问答区域。

### 5.5 项目与作品

- 项目名称、封面、简介、技术标签、状态与时间。
- 在线地址、代码地址、项目截图和详细说明。
- 支持按类型、年份、技术和状态筛选。
- 支持置顶、推荐和自定义排序。

### 5.6 友链

- 网站头像、名称、简介、地址、站长昵称和标签。
- 分类展示、搜索和随机排列。
- 友链申请、管理员审核和申请状态查询。
- 定时检查链接可用性，并在后台提示异常链接。

### 5.7 动态或说说

- 支持短文字、图片、表情、地点、心情和标签。
- 支持时间线、日历或卡片视图。
- 可选点赞和评论。
- 后台支持草稿、定时发布和可见范围。

### 5.8 相册

- 相册分类、图片瀑布流、描述、时间和地点。
- 图片灯箱、懒加载和渐进式加载。
- 可控制EXIF信息是否公开。
- 支持公开、私密或密码访问等权限扩展。

### 5.9 归档、搜索、留言与其他页面

- 归档按年份和月份展示文章、动态及项目更新。
- 全站搜索覆盖文章、项目、动态、页面、分类和标签。
- 留言板采用便利贴墙样式，支持回复、点赞、置顶和审核。
- 提供分类页、标签页、订阅页、RSS、隐私政策、版权说明、404、维护页、登录页和自定义独立页面。

## 6. 导航与物理动效

### 6.1 导航

- 桌面端使用可收起的悬浮软糖菜单。
- 移动端使用底部悬浮导航，保留首页、文章、动态、友链和更多入口。
- 当前页面使用柔和底色、图标和文字共同标识。
- 页面切换保留合理滚动状态，并提供轻量加载进度。

### 6.2 动效原则

动效关键词为“轻、软、弹、自然停止”：

- 按钮悬停轻微上浮，按下缩放至0.96～0.98。
- 卡片悬停可轻微上浮或倾斜，移动端使用点击反馈替代。
- 菜单采用分段展开和柔和回弹。
- 页面内容淡入并小幅上移，卡片可错峰出现。
- 图片先显示占位色或模糊缩略图，再渐进清晰。
- 点赞、收藏和成功状态使用简短弹跳反馈。

性能规则：

- 优先只对`transform`和`opacity`制作动画。
- 避免持续的大面积模糊、阴影、滤镜和复杂粒子效果。
- 用户开启“减少动态效果”后，关闭视差、漂浮、倾斜和弹簧动效。
- 低性能设备使用更简单的过渡，不影响任何业务功能。

## 7. 后台管理规划

后台延续前台色彩和圆角语言，但减少装饰并提高信息密度。

| 前台区域 | 后台对应能力 |
| --- | --- |
| 首页 | 模块开关、排序、布局、内容和展示数量 |
| 博客 | 文章增删改、草稿、发布、分类、标签和筛选规则 |
| 文章详情 | 编辑器、封面、SEO、目录、版权、推荐和历史版本 |
| 关于我 | 介绍、技能、经历、目标、联系方式和简历 |
| 项目作品 | 项目、截图、链接、状态、标签和排序 |
| 友链 | 友链、分类、申请审核、排序和可用性检查 |
| 动态 | 发布、定时发布、图片、可见范围和评论管理 |
| 相册 | 相册分类、批量上传、压缩、描述、EXIF和权限 |
| 留言与评论 | 审核、回复、置顶、屏蔽和反垃圾 |
| 搜索 | 索引状态、关键词统计和热词管理 |
| 导航与页脚 | 菜单、图标、顺序、跳转方式、版权和备案信息 |
| 主题 | 配色、字体、圆角、阴影、背景、布局和动效等级 |
| SEO | 标题模板、描述、分享图、站点地图和索引开关 |
| 系统 | 用户、角色、权限、日志、缓存、备份和系统状态 |

### 7.1 仪表盘

- 文章、草稿、评论、留言、友链申请等数据概览。
- 访问趋势、热门文章和常用快捷操作。
- 最近操作、待处理事项和系统健康状态。

### 7.2 内容编辑器

- Markdown或所见即所得编辑，以及分屏预览。
- 自动保存、草稿恢复、历史版本和发布预览。
- 图片拖拽与粘贴上传。
- 代码、表格、引用、提示块及可扩展内容组件。
- 定时发布、SEO预览、封面和摘要设置。

### 7.3 媒体库

- 单个或批量上传、标签分类、搜索和重复文件检测。
- 自动压缩、响应式缩略图和现代图片格式转换。
- 图片替代文字、引用状态和未使用文件检查。
- 媒体文件固定使用本地存储，按年月或内容哈希分目录，文件名不可由用户输入直接决定。
- 自动生成本地缩略图和响应式尺寸，数据库只保存相对路径与元数据。
- 提供本地媒体目录与SQLite数据库的一致性检查、打包备份和恢复能力。

### 7.4 用户与权限

建议包含超级管理员、管理员、编辑、作者和普通用户。权限细分到查看、新建、编辑、发布、删除、审核和系统设置，所有关键后台操作保留日志。

## 8. 核心数据模型

主要实体包括：

- 用户、角色、权限和登录记录。
- 文章、文章版本、分类、标签和关联关系。
- 评论、回复、点赞和审核记录。
- 项目、项目图片和项目标签。
- 动态、动态图片和动态互动。
- 相册、照片和媒体文件。
- 友链、友链分类、友链申请和检查记录。
- 留言、页面、导航菜单、首页模块和系统设置。
- 通知、访问统计、任务记录和操作日志。

主要内容实体统一包含创建时间、修改时间、发布状态、排序值、置顶状态、推荐状态、SEO信息、创建者、最后编辑者和软删除状态。

## 9. Flask本地化技术架构

### 9.1 应用结构

- 使用Flask应用工厂创建应用，配置开发、测试和生产环境。
- 使用Blueprint拆分公开站点、博客、个人内容、互动、认证、后台管理和API。
- 使用Jinja2模板继承、宏和组件化局部模板复用UI。
- 使用服务层承载业务规则，路由只负责参数接收、权限检查和响应组织。
- 使用仓储或查询模块集中复杂SQL，避免模板和路由中散落数据访问逻辑。
- 前后台共用一个代码库、一个SQLite数据库和一套设计变量，但路由、权限和模板目录清晰隔离。

### 9.2 建议本地依赖

- Flask：Web框架与路由。
- SQLAlchemy与Flask-SQLAlchemy：数据模型和查询。
- Alembic与Flask-Migrate：数据库迁移。
- Flask-Login：后台会话认证。
- Flask-WTF/WTForms：表单、校验和CSRF防护。
- Pillow：图片检查、压缩和缩略图生成。
- Markdown解析与HTML清理库：文章渲染和XSS防护。
- Waitress或Gunicorn：生产WSGI服务。
- pytest：测试。

依赖版本写入锁定文件；部署包可附带本地`wheelhouse`，使用离线方式安装。浏览器端库必须放入项目静态目录，不从远程地址加载。

### 9.3 SQLite策略

- 数据库位于`instance/data/site.db`一类的非源码目录，不提交真实生产数据。
- 每个连接启用`foreign_keys=ON`、`journal_mode=WAL`和合理的`busy_timeout`。
- 生产环境根据可靠性要求使用`synchronous=NORMAL`或更严格设置。
- 请求事务必须短小，不在事务内执行图片处理、网络等待或大文件操作。
- 为发布时间、状态、排序、分类、标签和关联外键建立针对性索引。
- 列表页面只查询需要字段，使用分页并避免N+1查询。
- 搜索优先使用SQLite FTS5；运行环境缺少FTS5时提供普通索引查询降级。
- 写入任务避免同时并发执行；备份、索引维护和友链检查使用本地CLI命令串行处理。
- 定期执行在线备份、完整性检查和可控的WAL checkpoint。

### 9.4 本地文件与静态资源

- 上传文件存放在实例目录，模板与版本化静态资源位于项目源码目录。
- 字体、图标、CSS、JavaScript、编辑器资源和语法高亮资源全部本地提供。
- 静态文件使用内容哈希或版本号生成长期缓存地址。
- 图片上传后验证真实格式，生成多尺寸缩略图，移除不必要元数据，并保留可配置的原图策略。
- 数据库与上传目录作为一个备份单元，恢复时校验两者一致性。

### 9.5 部署模型

- 首选单机部署，应用实例与SQLite数据库位于同一台机器的本地磁盘。
- Linux使用Gunicorn运行Flask，Windows使用Waitress；禁止使用Flask开发服务器承载生产流量。
- 可选本地Nginx/Caddy等反向代理处理HTTPS、压缩和静态文件，但网站不能依赖外部CDN。
- SQLite不放置在网络共享盘，不由多台应用服务器同时写入。
- 生产发布采用版本目录、虚拟环境、实例数据目录分离的方式，便于升级和回滚。

## 10. 性能与兼容要求

- Jinja2直接输出首屏关键HTML，核心功能在JavaScript不可用时仍可完成。
- 对公开且变化较少的页面使用进程内TTL缓存或本地文件缓存，并在后台修改内容后精确失效。
- 缓存不能成为数据真相来源；多进程缓存允许短时间不一致，关键数据始终读取SQLite。
- 使用条件请求、ETag、`Last-Modified`、压缩和合理的浏览器缓存头。
- 图片按设备尺寸加载，使用本地缩略图、懒加载、尺寸占位和渐进显示。
- 控制本地字体数量并使用字体子集，首屏字体采用合理的回退策略。
- 长列表使用游标或分页；后台大列表禁止一次加载全部记录。
- 所有静态资源由本机或本地反向代理提供，不使用CDN。
- 后台图表、编辑器和代码高亮等较重资源按页面加载。
- 定期检查慢查询、缺失索引、N+1查询、SQLite锁等待和WAL文件增长。
- 对首页、文章详情和列表页建立可重复的性能基准，优化前后对比结果。
- 支持主流桌面浏览器、常见Android设备、iPhone和iPad。
- 性能目标以单机读多写少为前提；持续高并发写入不属于当前架构承诺范围。

## 11. 无障碍与安全

### 11.1 无障碍

- 支持键盘操作、清晰的焦点状态和语义化结构。
- 图片支持替代文本，表单包含标签和明确错误提示。
- 弹窗正确管理焦点，关闭方式明确。
- 正文支持浏览器字体缩放。
- 支持减少动画设置，且关闭动画不影响功能。

### 11.2 安全

- 密码安全存储，登录失败限制，可扩展双重验证。
- 服务端执行权限校验、输入验证和输出过滤。
- 防护CSRF、XSS、SQL注入、暴力登录和垃圾信息。
- 检查上传文件类型、扩展名、大小和实际内容。
- 重要操作二次确认并记录审计日志。
- 定期备份数据库和媒体，并验证恢复流程。
- 后台页面禁止被搜索引擎收录。

## 12. SEO与传播

- 每个公开页面支持标题、描述、规范链接和分享封面。
- 自动生成站点地图、RSS和结构化数据。
- 文章使用稳定永久链接，修改标题不破坏原地址。
- 提供语义化标题、面包屑、404和重定向管理。
- 后台可单独控制页面是否允许索引。

## 13. 总体验收标准

- 所有前台内容都有完整后台管理入口。
- 首页模块可以开启、关闭、排序并调整主要展示参数。
