# 需求规格与版本范围

## 1. 产品目标

构建一个具有独特可爱浅色视觉的个人网站，承担以下用途：

- 长期发布和归档博客文章。
- 展示个人介绍、经历、技能、项目和联系方式。
- 发布短动态与相册内容。
- 维护友情链接并接收友链申请。
- 通过评论和留言与访客互动。
- 通过完整后台管理前台全部内容、导航、主题和系统设置。

网站应优先满足个人长期维护、内容可控、运行稳定和本地数据自主，不以社交平台或大型内容平台为目标。

## 2. 用户角色与主要场景

### 2.1 公开访客

- 浏览首页、文章、项目、动态、相册、友链和关于页面。
- 搜索、按分类标签筛选和查看归档。
- 提交评论、留言和友链申请。
- 使用键盘、触控或鼠标操作，并可选择减少动画。

### 2.2 作者与编辑

- 登录后台创建、编辑和预览被授权的内容。
- 管理文章草稿、分类、标签、项目、动态和媒体。
- 编辑只能执行被分配的管理权限，不能修改系统安全设置。

### 2.3 管理员

- 管理所有内容、审核、导航、主题、用户、角色和系统设置。
- 查看操作日志、登录日志、数据库状态和备份状态。
- 执行备份、恢复前检查、搜索索引维护和本地媒体一致性检查。

## 3. 首发版本范围（MVP）

首发版本必须形成完整可用闭环，而不是仅有静态页面。

### 3.1 前台

- 响应式首页与可配置模块。
- 博客列表、文章详情、分类、标签、归档、搜索和 RSS。
- 关于我、经历时间线和联系方式。
- 项目列表与详情。
- 动态列表与详情。
- 相册列表、照片展示和本地图片灯箱。
- 友链展示与申请。
- 评论和留言板。
- 自定义独立页面、导航、页脚、404与错误页面。

### 3.2 后台

- 管理员登录、退出、会话与权限校验。
- 仪表盘和待审核事项。
- 文章、分类、标签和文章版本管理。
- 个人资料、经历、项目、动态和相册管理。
- 友链、友链申请、评论和留言审核。
- 本地媒体库。
- 首页模块、导航、页脚、主题和 SEO 设置。
- 用户、角色、操作日志、备份记录和系统状态。

### 3.3 系统能力

- SQLite 迁移、初始化、在线备份与完整性检查。
- 本地全文搜索或兼容降级搜索。
- 图片格式校验、缩略图、尺寸占位与懒加载。
- CSRF、防注入、输出清理、登录限制和提交限流。
- 性能、错误和审计日志。

## 4. 首发后扩展范围

以下功能预留接口但不阻塞首发：

- 深色主题和多套可切换主题。
- 私密文章、相册密码和细粒度访客账户。
- 邮件通知、第三方登录和 Webhook。
- 多语言。
- 插件系统与主题市场。
- 多站点、多租户和独立搜索服务。
- 多机部署及其他数据库迁移。

扩展功能不能提前增加首发架构复杂度。

## 5. 功能规则

### 5.1 内容发布

- 内容至少具有草稿、已发布、已归档三种状态。
- 定时文章只有到达发布时间后才对访客公开。
- 删除内容默认进入回收站，管理员可恢复或永久删除。
- 已发布文章保存历史版本，修改后可查看差异和恢复。
- URL 标识发布后保持稳定，标题变化不自动改变永久链接。

### 5.2 互动审核

- 评论、留言和友链申请提交后必须经过服务端校验。
- 匿名提交使用昵称和可选联系方式，联系方式不在前台公开。
- 待审核、已拒绝、垃圾内容不会出现在公开页面。
- 管理员的回复和审核操作记录操作者与时间。

### 5.3 媒体

- 浏览器上传文件名不直接作为磁盘文件名。
- 服务端检查文件大小、实际格式和允许类型。
- 原图保留策略可配置，公开页面优先加载缩略图或适配尺寸。
- 删除被内容引用的媒体前必须提示引用关系。

### 5.4 配置

- 首页主要模块、导航、页脚和公开联系方式均可从后台维护。
- 安全相关配置不能通过普通编辑角色修改。
- 配置修改需要校验，并对影响页面缓存的修改进行失效处理。

## 6. 非功能要求

### 6.1 性能

- 采用服务端渲染，首屏不依赖大型客户端框架。
- 公开列表必须分页，禁止一次加载全部数据。
- 文章和首页避免 N+1 查询，常用条件必须建立索引。
- 静态资源使用版本化地址、缓存头与压缩。
- 图片必须包含尺寸信息，避免加载造成布局跳动。
- 性能结论必须注明机器、数据量、并发模型和测试方法。

### 6.2 兼容与可访问

- 支持主流桌面浏览器、Android 浏览器、iPhone 和 iPad。
- 核心操作支持键盘，焦点清晰，表单包含标签和错误描述。
- 用户选择减少动态效果后关闭非必要物理动画。
- JavaScript 失败时仍可浏览内容并提交核心服务端表单。

### 6.3 安全与隐私

- 密码只保存安全哈希，密钥通过环境或实例配置提供。
- 所有写入请求执行认证/授权、CSRF 和输入校验。
- Markdown 或富文本输出必须清理危险 HTML。
- 后台、日志、备份、SQLite 文件和上传原始路径不得公开暴露。
- 联系方式、IP 与审核信息按最少必要原则保存。

### 6.4 可维护性

- 模块职责清晰，路由不直接堆积复杂业务逻辑。
- 数据库结构变更必须通过迁移文件。
- 关键业务规则、权限和备份恢复必须有自动化测试。
- 项目在已准备依赖的环境中断网后仍能完整运行。

## 7. 验收用核心用户旅程

1. 管理员登录后台，创建分类和标签，撰写文章，上传封面并预览发布。
2. 访客从首页进入文章详情，通过分类、归档与搜索找到文章。
3. 访客提交评论，管理员在后台审核并回复，公开页面正确展示。
4. 管理员修改个人资料、首页模块、导航和友链，前台缓存正确刷新。
5. 管理员创建项目、动态和相册，移动端正确展示本地图片。
6. 运维人员执行SQLite和媒体联合备份，在测试实例完成恢复验证。

## 8. 明确不承诺事项

- 不承诺SQLite支撑持续的大规模并发写入。
- 不承诺多台应用服务器共同写入同一数据库。
- 不使用网络共享盘保存SQLite数据库。
- 不依赖外部CDN、对象存储、Redis或云数据库提高性能。
- 首发不实现公开注册、实时聊天、付费订阅或复杂社交关系。
