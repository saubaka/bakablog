# 本地依赖与资产策略

## 1. 目标

项目完成首次依赖准备后，应能在断网环境运行、测试和提供完整页面。生产请求不能向外部CDN、字体服务、云数据库、对象存储或远程搜索服务获取必需资源。

## 2. Python基线

- 使用仍处于安全支持周期的稳定Python 3版本；具体小版本在阶段三初始化时根据本机可用环境锁定。
- 项目虚拟环境固定使用根目录`.venv`。
- 直接依赖与传递依赖均锁定版本。
- 生产与开发依赖分开，生产环境不安装测试、格式化和调试工具。
- 不从未审核脚本动态下载或执行代码。

## 3. 建议生产依赖类别

| 类别 | 首选用途 | 是否必须 |
| --- | --- | --- |
| Flask | Web框架与Jinja2集成 | 必须 |
| Flask-SQLAlchemy / SQLAlchemy | SQLite模型与查询 | 必须 |
| Flask-Migrate / Alembic | 数据库迁移 | 必须 |
| Flask-Login | 后台会话认证 | 必须 |
| Flask-WTF / WTForms | 表单验证和CSRF | 必须 |
| Pillow | 本地图片验证和缩略图 | 必须 |
| Markdown解析库 | 文章源内容转换 | 必须 |
| HTML清理库 | 富文本允许列表清理 | 必须 |
| Waitress | Windows生产WSGI | Windows部署必须 |
| Gunicorn | Linux生产WSGI | Linux部署必须 |

可选能力优先使用Python标准库或小型、维护活跃、许可证明确的库。依赖的最终包名和版本必须在阶段三通过兼容性测试后写入锁定文件。

## 4. 开发依赖类别

- pytest及Flask测试辅助。
- 覆盖率工具。
- Python格式化、静态检查和类型检查工具。
- 依赖漏洞与许可证检查工具。
- 本地HTTP性能测试工具；不能成为生产运行依赖。

## 5. 离线安装

推荐流程：

1. 在有网络且可信的准备环境生成锁定依赖。
2. 下载与目标Python、操作系统和架构匹配的wheel到`wheelhouse/`。
3. 记录包名、版本、文件哈希和许可证。
4. 在干净环境使用`--no-index --find-links`验证离线安装。
5. 执行导入检查、数据库初始化和完整测试。

不得把不匹配平台的wheel当作通用离线包。Windows和Linux需要分别准备带原生扩展的包。

## 6. 浏览器端资源

### 6.1 默认策略

- 优先使用原生CSS、CSS变量、Web Animations API和小型原生JavaScript模块。
- 不引入React、Vue等全站客户端运行时。
- 图标优先使用本地SVG精灵或经过清理的内联SVG。
- 字体使用本地文件并提供系统字体回退，不访问在线字体服务。
- Markdown代码高亮的样式和脚本放在`static/vendor`并按文章页面加载。

### 6.2 第三方前端资源准入

每个第三方资源必须记录：

- 名称、版本、来源、许可证和文件哈希。
- 使用页面、是否可替代、升级方式和安全注意事项。
- 已复制到项目的本地路径。
- 断网测试结果。

不允许模板包含远程`script`、`link`、`font`或必需图片URL。

## 7. 更新策略

- 依赖更新单独提交并运行完整测试。
- 安全修复优先于功能升级。
- 不自动更新生产依赖。
- 更新前备份锁定文件和wheel清单，失败时可恢复上一组依赖。
- 浏览器资源更新后变更静态版本或内容哈希，避免旧缓存混用。

## 8. 许可证与供应链

- 只引入许可证允许随项目分发和本地托管的资源。
- 保存第三方许可声明和必要版权信息。
- 锁定下载哈希，避免同版本文件被替换。
- 不提交来源不明的字体、图标或脚本。
- 生产部署只从锁定文件和可信本地wheel目录安装。

## 9. 验收标准

- 在干净虚拟环境中可从锁定依赖安装。
- 已准备wheel时可以完全离线安装。
- 断网后公开页面、后台、字体、图标、编辑器和图片功能正常。
- 页面源码和网络请求中不存在未经批准的远程资源。
- 所有第三方资源都有版本、许可证和本地路径记录。
